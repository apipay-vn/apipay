# Payment Requests API

API dùng để tạo và quản lý payment link.

## Tạo payment link

Tạo link thanh toán bằng tài khoản ngân hàng đã kết nối.

```bash
POST /v1/client/payment-requests
```

### Headers

| Header          | Mô tả              |
| --------------- | ------------------ |
| `Authorization` | `Bearer <Auth>`    |
| `Content-Type`  | `application/json` |

> **Lưu ý:** `<Auth>` là chuỗi base64 của `accessKey:secretKey`. Xem [Xác thực API](/vi/api/authentication) để biết chi tiết.

### Request Body

| Tham số        | Kiểu   | Bắt buộc | Mô tả                                                                                                                                                                            |
| -------------- | ------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bankPublicId` | string | **✓ Có** | Public ID của ngân hàng đã kết nối                                                                                                                                               |
| `amount`       | string | —        | Số tiền VND (chuỗi số nguyên hoặc số, tối đa `300000000`). Trả về dưới dạng chuỗi hoặc `null`. Để trống nếu cho phép khách tự nhập                                                |
| `content`      | string | —        | Nội dung chuyển khoản (tối đa 140 ký tự)                                                                                                                                         |
| `title`        | string | —        | Tiêu đề hiển thị trên trang thanh toán                                                                                                                                           |
| `expiresAt`    | string | —        | Thời hạn (ISO 8601). Để trống nếu không giới hạn                                                                                                                                 |
| `redirectUrl`  | string | —        | URL đưa khách về sau khi thanh toán. Khi hoàn tất, hệ thống chuyển đến URL này kèm payload đã ký (`?data=<base64>&signature=<hmac>`). Để trống để dùng URL mặc định của merchant |

### Response

```json
{
  "data": {
    "publicId": "APIPAYJSCAF9H23M74K",
    "payUrl": "https://pay.apipay.vn/APIPAYJSCAF9H23M74K",
    "qrUrl": "https://api.qrserver.com/v1/create-qr-code?...",
    "bankCode": "MB",
    "accountNumber": "0123456789",
    "accountName": "NGUYEN VAN A",
    "amount": "100000",
    "content": "ORDER-12345",
    "expiresAt": "2026-12-31T23:59:59Z",
    "createdAt": "2026-03-06T10:00:00Z",
    "redirectSecret": "a1b2c3d4e5f6..."
  },
  "statusCode": 200,
  "timestamp": "2026-08-12T14:27:45.000Z"
}
```

### Ví dụ

```bash
curl -X POST https://app.apipay.vn/v1/client/payment-requests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "bankPublicId": "bank_abc123",
    "amount": "500000",
    "content": "THANHTOAN-001",
    "title": "DON HANG 12345",
    "redirectUrl": "https://yoursite.com/payment/result"
  }'
```

## Lấy thông tin payment link

Lấy chi tiết một payment request, gồm cả QR code.

```bash
GET /v1/payment-requests/:publicId
```

### Response

```json

  "data": {
    "publicId": "APIPAYJSCAF9H23M74K",
    "bankCode": "MB",
    "accountNumber": "0123456789",
    "accountName": "NGUYEN VAN A",
    "amount": "100000",
    "content": "ORDER-12345",
    "title": "DON HANG 12345",
    "status": "ACTIVE",
    "qrUrl": "https://api.qrserver.com/...",

    "createdAt": "2026-03-06T10:00:00Z",
    "canChangeBank": true,
    "bankChangedByCustomer": false,
    "redirectUrl": "https://yoursite.com/payment/result",
```

### Status

| Status      | Mô tả               |
| ----------- | ------------------- |
| `ACTIVE`    | Đang chờ thanh toán |
| `COMPLETED` | Đã thanh toán       |
| `EXPIRED`   | Đã hết hạn          |
| `CANCELLED` | Đã hủy              |

## Danh sách payment links

Lấy danh sách payment requests đã tạo. Dữ liệu endpoint nằm trong `data` ở cấp cao nhất; các endpoint danh sách do đó sẽ có `data.data` chứa danh sách các dòng.

```bash
GET /v1/client/payment-requests
```

### Headers

| Header          | Mô tả           |
| --------------- | --------------- |
| `Authorization` | `Bearer <Auth>` |

### Response

```json
{
  "data": {
    "status": true,
    "data": [
      {
        "publicId": "APIPAYJSCAF9H23M74K",
        "bankCode": "MB",
        "accountNumber": "0123456789",
        "accountName": "NGUYEN VAN A",
        "amount": "100000",
        "content": "ORDER-001",
        "title": "DON HANG 12345",
        "status": "COMPLETED",
        "expiresAt": "2026-12-31T23:59:59Z",
        "redirectUrl": "https://yoursite.com/payment/result",
        "createdAt": "2026-03-06T10:00:00Z"
      }
    ],
    "pagination": {
      "page": 1,
      "limit": 20,
      "total": 1,
      "totalPages": 1
    }
  },
  "statusCode": 200,
  "timestamp": "2026-08-12T14:27:45.000Z"
}
```

### Query Parameters

| Tham số         | Kiểu     | Bắt buộc | Mô tả                                                                                       |
| --------------- | -------- | -------- | ------------------------------------------------------------------------------------------- |
| `page`          | number   | —        | Số trang (mặc định: `1`)                                                                    |
| `limit`         | number   | —        | Số item trên mỗi trang (mặc định: `20`, tối đa: `100`)                                      |
| `search`        | string   | —        | Tìm theo public ID, nội dung, tiêu đề hoặc số tài khoản                                     |
| `status`        | string[] | —        | Lọc theo trạng thái: `ACTIVE`, `EXPIRED`, `COMPLETED`, `CANCELLED`. Có thể truyền nhiều lần |
| `bankAccountId` | number   | —        | Lọc theo ID tài khoản ngân hàng                                                             |
| `dateFrom`      | string   | —        | Lọc theo ngày tạo từ ngày ISO này                                                           |
| `dateTo`        | string   | —        | Lọc theo ngày tạo đến ngày ISO này                                                          |

### Bộ lọc status

Query parameter `status` nhận các giá trị sau:

| Status      | Mô tả               |
| ----------- | ------------------- |
| `ACTIVE`    | Đang chờ thanh toán |
| `COMPLETED` | Đã thanh toán       |
| `EXPIRED`   | Đã hết hạn          |
| `CANCELLED` | Đã hết hạn          |

### Ví dụ query

Lấy payment links đã thanh toán:

```bash
curl -G https://app.apipay.vn/v1/client/payment-requests \
  -H "Authorization: Bearer <Auth>" \
  --data-urlencode "status=COMPLETED" \
  --data-urlencode "page=1" \
  --data-urlencode "limit=20"
```

Lấy payment links đang hoạt động hoặc đã hết hạn được tạo trong tháng 3/2026:

```bash
curl -G https://app.apipay.vn/v1/client/payment-requests \
  -H "Authorization: Bearer <Auth>" \
  --data-urlencode "status=ACTIVE" \
  --data-urlencode "status=EXPIRED" \
  --data-urlencode "dateFrom=2026-03-01" \
  --data-urlencode "dateTo=2026-03-31"
```

## Đổi ngân hàng thanh toán

Đổi một payment request đang hoạt động sang tài khoản ngân hàng khác đã cấu hình.

```bash
POST /v1/payment-requests/change-bank
```

### Request Body

| Tham số        | Kiểu   | Bắt buộc | Mô tả                                       |
| -------------- | ------ | -------- | ------------------------------------------- |
| `publicId`     | string | **✓ Có** | Public ID của payment request               |
| `bankPublicId` | string | **✓ Có** | Public ID của tài khoản ngân hàng được chọn |

### Response

## Hủy Payment Link

Hủy một payment request đang hoạt động.

```bash
DELETE /v1/client/payment-requests/:publicId
```

### Response

```json
{
  "data": {
    "status": true,
    "message": "Payment request cancelled"
  },
  "statusCode": 200,
  "timestamp": "2026-08-12T14:27:45.000Z"
}
```

### Lưu ý

- Chỉ có thể hủy payment request có status là `ACTIVE`
- Sau khi hủy, status sẽ chuyển thành `CANCELLED`

## Xác minh signed redirect URL

Khi tạo payment request có `redirectUrl`, sau khi thanh toán xong, khách sẽ được chuyển về URL của bạn kèm payload đã ký.

### Định dạng redirect

Sau khi thanh toán xong, khách được chuyển đến:

```
https://yoursite.com/payment/result?data=<base64>&signature=<hmac>
```

### Cấu trúc payload

Tham số `data` chứa JSON được mã hóa base64:

```json
{
  "status": "success",
  "transactionId": "txn_abc123",
  "amount": "100000",
  "content": "ORDER-12345",
  "timestamp": 1700000000
}
```

Các giá trị `status` có thể: `success`, `cancel`, `expired`

### Ví dụ xác minh

<CodeTabs>
```javascript
// Node.js example
const crypto = require('crypto');

function verifyRedirectPayload(query, redirectSecret) {
// Giải mã payload
const payloadJson = Buffer.from(query.data, 'base64url').toString('utf-8');
const payload = JSON.parse(payloadJson);

// Tính signature mong đợi
const expectedSignature = crypto.createHmac('sha256', redirectSecret).update(payloadJson).digest('hex');

// Sử dụng timing-safe comparison để chống timing attacks
const isValid = crypto.timingSafeEqual(Buffer.from(query.signature), Buffer.from(expectedSignature));

if (!isValid) {
throw new Error('Invalid signature');
}

return payload;
}

// Express route handler
app.get('/payment/result', (req, res) => {
const {data, signature} = req.query;
const redirectSecret = 'a1b2c3d4e5f6...'; // Từ payment request response

try {
const payload = verifyRedirectPayload({data, signature}, redirectSecret);
console.log('Payment status:', payload.status);
console.log('Transaction ID:', payload.transactionId);
console.log('Amount:', payload.amount);

    if (payload.status === 'success') {
      // Xử lý thanh toán
      res.send('Thanh toán thành công!');
    }

} catch (error) {
res.status(400).send('Invalid redirect');
}
});

````

```python
import hmac
import hashlib
import base64
import json

def verify_redirect_payload(query: dict, redirect_secret: str) -> dict:
    # Decode the base64url-encoded payload
    # Add padding if needed for standard base64 decoding
    data = query['data']
    padding = 4 - len(data) % 4
    if padding != 4:
        data += '=' * padding
    payload_json = base64.urlsafe_b64decode(data).decode('utf-8')
    payload = json.loads(payload_json)

    # Calculate expected signature
    expected_signature = hmac.new(
        redirect_secret.encode(),
        payload_json.encode(),
        hashlib.sha256
    ).hexdigest()

    # Use timing-safe comparison to prevent timing attacks
    if not hmac.compare_digest(query['signature'], expected_signature):
        raise ValueError('Invalid signature')

    return payload

# FastAPI route handler
@app.get('/payment/result')
def handle_redirect(data: str, signature: str):
    redirect_secret = 'a1b2c3d4e5f6...'  # From payment request response

    try:
        payload = verify_redirect_payload({'data': data, 'signature': signature}, redirect_secret)
        print(f"Payment status: {payload['status']}")
        print(f"Transaction ID: {payload['transactionId']}")
        print(f"Amount: {payload['amount']}")

        if payload['status'] == 'success':
            # Process the payment
            return {'message': 'Payment successful'}
    except ValueError:
        from fastapi import HTTPException
        raise HTTPException(status_code=400, detail='Invalid redirect')
````

```php
<?php

use Illuminate\Http\Request;

function verifyRedirectPayload(array $query, string $redirectSecret): array
{
    // Decode the base64url-encoded payload
    $data = strtr($query['data'], '-_', '+/');
    $payloadJson = base64_decode($data);
    $payload = json_decode($payloadJson, true);

    // Calculate expected signature
    $expectedSignature = hash_hmac('sha256', $payloadJson, $redirectSecret);

    // Use timing-safe comparison to prevent timing attacks
    if (!hash_equals($query['signature'], $expectedSignature)) {
        throw new \RuntimeException('Invalid signature');
    }

    return $payload;
}

// Laravel route handler
Route::get('/payment/result', function (Request $request) {
    $redirectSecret = 'a1b2c3d4e5f6...'; // From payment request response

    try {
        $payload = verifyRedirectPayload($request->query(), $redirectSecret);
        \Log::info('Payment status: ' . $payload['status']);
        \Log::info('Transaction ID: ' . $payload['transactionId']);
        \Log::info('Amount: ' . $payload['amount']);

        if ($payload['status'] === 'success') {
            // Process the payment
            return response('Payment successful!');
        }
    } catch (\RuntimeException $e) {
        abort(400, 'Invalid redirect');
    }
});
```

### Trường Response

Khi tạo payment request, bạn nhận được:

| Trường                 | Mô tả                                                                           |
| ---------------------- | ------------------------------------------------------------------------------- |
| `redirectSecret`       | Khóa bí mật (32 ký tự hex) để xác minh signed redirect payload. **Giữ bí mật!** |
| `completedRedirectUrl` | Full signed URL sau khi thanh toán hoàn tất. Chỉ dùng để tham khảo              |

### Lưu ý bảo mật

- **Luôn kiểm tra signature** trước khi xử lý thanh toán
- Dùng `timingSafeEqual` để chống timing attacks
- `redirectSecret` là duy nhất cho mỗi payment request
- Không để lộ `redirectSecret` trong client-side code
- Kiểm tra `status === 'success'` trước khi xử lý đơn hàng
