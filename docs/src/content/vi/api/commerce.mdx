# Commerce API

API Commerce để tạo sản phẩm và mức giá. Xác thực giống mọi endpoint `/v1/client/*`. Xem [Xác thực](/vi/api/authentication).

Khi đã có mức giá, tạo link thanh toán bằng `priceId` trên [Payment Requests](/vi/api/payment-requests). Có thể thử các lệnh này trong [Interactive Reference](/vi/api-reference).

<Callout type="info">
Khi tạo payment, gửi `priceId` **hoặc** `amount` — không gửi cả hai. Số tiền được ghi vào link một lần. Sửa sản phẩm hoặc mức giá sau đó không làm đổi các link đã tạo.
</Callout>

## Endpoint

Mọi path nằm dưới `/v1/client/commerce`.

| Method | Path | Mô tả |
| ------ | ---- | ----- |
| `POST` | `/products` | Tạo sản phẩm. `defaultPriceData` tùy chọn tạo mức giá đầu và đặt làm mặc định |
| `GET` | `/products` | Danh sách sản phẩm (`active`, `page`, `limit`) |
| `GET` | `/products/:id` | Lấy sản phẩm kèm các mức giá |
| `PATCH` | `/products/:id` | Cập nhật tên, mô tả, ảnh (`imageId`), lưu trữ/khôi phục, hoặc giá mặc định |
| `POST` | `/prices` | Tạo mức giá. Mức giá đầu trên sản phẩm chưa có mặc định sẽ thành mặc định |
| `GET` | `/prices` | Danh sách mức giá (`productId`, `lookupKey`, `active`, `page`, `limit`) |
| `GET` | `/prices/:id` | Lấy một mức giá |
| `PATCH` | `/prices/:id` | Cập nhật `active`, `nickname`, `lookupKey`. Không đổi `unitAmount` |
| `GET` | `/invoices` | Danh sách hóa đơn bán hàng (`search`, `page`, `limit`) |
| `GET` | `/invoices/:id` | Chi tiết hóa đơn bán hàng kèm line items |
| `GET` | `/invoices/:id/pdf` | Tải file PDF hóa đơn / biên lai bán hàng |
| `PATCH` | `/invoices/:id` | Cập nhật thông tin người mua (`buyerName`, `buyerEmail`, `buyerTaxCode`, `buyerAddress`) |

Công khai (không cần auth), dùng bởi `pay.apipay.vn`:

| Method | Path | Mô tả |
| ------ | ---- | ----- |
| `GET` | `/v1/commerce/payment-links/:publicId` | Tên sản phẩm, số tiền, và branding merchant của link thanh toán dùng lại |
| `POST` | `/v1/commerce/payment-links/:publicId/checkout` | Thu thập thông tin người mua và tạo yêu cầu thanh toán một lần |
| `PATCH` | `/v1/payment-requests/:cuid/customer` | Thu thập thông tin người mua trên yêu cầu thanh toán commerce đã có, trước khi họ trả |
| `POST` | `/v1/client/media` | Tải ảnh (multipart `file` + `kind=commerce_product`). Cần auth |
| `DELETE` | `/v1/client/media/:id` | Xóa ảnh bạn sở hữu. Cần auth |
| `GET` | `/v1/media/:id` | Tải bytes ảnh công khai (trang thanh toán và dashboard dùng URL này) |

Sản phẩm trả về `imageId` / `imageUrl`. Gắn ảnh: `POST /v1/client/media` rồi `PATCH /products/:id` với `imageId`. Gửi `imageId: null` để gỡ.

## Tạo sản phẩm

```bash
POST /v1/client/commerce/products
```

### Request body

| Tham số | Kiểu | Bắt buộc | Mô tả |
| ------- | ---- | -------- | ----- |
| `name` | string | **Có** | Tên sản phẩm (tối đa 200) |
| `description` | string | — | Mô tả tùy chọn (tối đa 2000) |
| `defaultPriceData` | object | — | Tạo mức giá đầu và đặt làm mặc định |
| `defaultPriceData.unitAmount` | string | **Có** nếu gửi `defaultPriceData` | Số tiền VND (chuỗi số nguyên, 1–300000000) |
| `defaultPriceData.lookupKey` | string | — | Mã ổn định bạn giữ trong app, ví dụ `pro-monthly` |
| `defaultPriceData.nickname` | string | — | Tên nội bộ, khách không thấy |

### Ví dụ

```bash
curl -X POST https://app.apipay.vn/v1/client/commerce/products \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "name": "Goi Pro",
    "description": "Truy cap hang thang",
    "defaultPriceData": {
      "unitAmount": "99000",
      "lookupKey": "pro-monthly",
      "nickname": "Gia ra mat"
    }
  }'
```

## Tạo mức giá

```bash
POST /v1/client/commerce/prices
```

Số tiền không sửa được sau khi tạo. Muốn đổi giá thì tạo mức giá mới và lưu trữ mức cũ.

### Request body

| Tham số | Kiểu | Bắt buộc | Mô tả |
| ------- | ---- | -------- | ----- |
| `productId` | string | **Có** | Sản phẩm chứa mức giá này |
| `unitAmount` | string | **Có** | Số tiền VND (chuỗi số nguyên, 1–300000000) |
| `lookupKey` | string | — | Mã ổn định, duy nhất trên tài khoản. Tra sau bằng `GET /prices?lookupKey=` |
| `nickname` | string | — | Tên nội bộ |
| `transferLookupKey` | boolean | — | Nếu `true`, chuyển `lookupKey` khỏi mức giá đang giữ mã đó thay vì báo lỗi |

### Ví dụ

```bash
curl -X POST https://app.apipay.vn/v1/client/commerce/prices \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "productId": "cml8x1abc0000prod0000000",
    "unitAmount": "199000",
    "lookupKey": "pro-yearly",
    "nickname": "Theo nam"
  }'
```

Nếu sản phẩm chưa có giá mặc định, mức giá này trở thành mặc định.

---

## Tìm mức giá theo lookup key

```bash
curl "https://app.apipay.vn/v1/client/commerce/prices?lookupKey=pro-monthly" \
  -H "Authorization: Bearer <Auth>"
```

Lấy `id` trả về làm `priceId` khi tạo thanh toán.

## Cập nhật sản phẩm

```bash
PATCH /v1/client/commerce/products/:id
```

| Tham số | Kiểu | Mô tả |
| ------- | ---- | ----- |
| `name` | string | Tên sản phẩm |
| `description` | string \| null | Gửi `null` để xóa |
| `active` | boolean | `false` lưu trữ, `true` khôi phục |
| `defaultPriceId` | string \| null | Phải là mức giá đang hoạt động của sản phẩm này. Gửi `null` để xóa |
| `imageId` | string \| null | Id ảnh từ `POST /v1/client/media`. Gửi `null` để gỡ |

---

## Cập nhật mức giá

```bash
PATCH /v1/client/commerce/prices/:id
```

| Tham số | Kiểu | Mô tả |
| ------- | ---- | ----- |
| `active` | boolean | `false` lưu trữ, `true` khôi phục |
| `nickname` | string \| null | Gửi `null` để xóa |
| `lookupKey` | string \| null | Gửi `null` để xóa |
| `transferLookupKey` | boolean | Chuyển `lookupKey` từ mức giá đang giữ mã đó |

Không nhận `unitAmount`. Mức giá đã lưu trữ không dùng để tạo link mới. Link tạo trước đó vẫn giữ mức giá lúc tạo (`commercePriceId` trên payment request).

## Tạo thanh toán từ mức giá

```bash
curl -X POST https://app.apipay.vn/v1/client/payment-requests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "bankPublicId": "bank_abc123",
    "priceId": "cml8x1abc0000price0000000",
    "content": "DONHANG-001"
  }'
```

Số tiền thanh toán lấy từ `unitAmount` của mức giá. Nếu bỏ `title`, hệ thống dùng tên sản phẩm. Bạn cũng có thể truyền thông tin khách hàng `customer` tùy chọn để tự động điền vào hóa đơn bán hàng:

```bash
curl -X POST https://app.apipay.vn/v1/client/payment-requests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "bankPublicId": "bank_abc123",
    "priceId": "cml8x1abc0000price0000000",
    "content": "DONHANG-001",
    "customer": {
      "name": "Nguyen Van A",
      "email": "customer@example.com",
      "taxCode": "0101234567",
      "address": "123 Le Loi, Ben Nghe, Q.1, TP.HCM"
    }
  }'
```

Xem [Payment Requests](/vi/api/payment-requests) cho response đầy đủ và [Webhook](/vi/api/webhooks) cho payload khi khách trả.

Mỗi mức giá còn có `paymentLinkUrl` dùng lại (`https://pay.apipay.vn/p/{publicId}`). Chia sẻ URL đó thay vì tạo payment request cho từng khách. Trang thanh toán thu thập họ tên và email, rồi tạo yêu cầu thanh toán mới. Sau thanh toán live, PDF biên lai được gửi tới email người mua.

## Hóa đơn bán hàng (Receipts)

Khi một yêu cầu thanh toán (chế độ Live) gắn với `commercePriceId` hoàn thành thanh toán, hệ thống tự động tạo một hóa đơn bán hàng (`CommerceInvoice`) đã thanh toán với định dạng số `CINV-YYYYMM-XXXX`.

<Callout type="warning">
**Lưu ý**: Hóa đơn bán hàng Commerce là biên lai ghi nhận thanh toán thương mại của người bán cấp cho khách hàng. Đây **không phải hóa đơn GTGT** (*"Đây không phải hóa đơn GTGT / This is not an official VAT invoice"*).
</Callout>

### Danh sách hóa đơn

```bash
GET /v1/client/commerce/invoices?search=CINV-202609&page=1&limit=20
```

| Query parameter | Kiểu | Mô tả |
| --------------- | ---- | ----- |
| `search` | string | Tìm kiếm theo số hóa đơn, tên người mua, email, hoặc tên sản phẩm |
| `page` | number | Trang (mặc định: 1) |
| `limit` | number | Số lượng mỗi trang (mặc định: 20, tối đa: 100) |

### Chi tiết hóa đơn

```bash
GET /v1/client/commerce/invoices/:id
```

Trả về thông tin chi tiết hóa đơn gồm bên bán, bên mua, tổng tiền và các dòng sản phẩm/dịch vụ (`lineItems`).

### Tải file PDF hóa đơn

```bash
GET /v1/client/commerce/invoices/:id/pdf
```

Trả về file nhị phân `application/pdf`, tên file tải về gợi ý `apipay-cinv-{invoiceNumber}.pdf`.

### Cập nhật thông tin người mua

```bash
PATCH /v1/client/commerce/invoices/:id
```

Cập nhật thông tin người mua trên hóa đơn đã phát hành:

```bash
curl -X PATCH https://app.apipay.vn/v1/client/commerce/invoices/cml8x1abc0000inv0000000 \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "buyerName": "Nguyen Van A",
    "buyerEmail": "buyer@example.com",
    "buyerTaxCode": "0101234567",
    "buyerAddress": "123 Le Loi, Q.1, TP.HCM"
  }'
```
