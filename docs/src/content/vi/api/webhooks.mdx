# Webhooks

Webhook giúp hệ thống của bạn nhận thông báo khi có sự kiện thanh toán.

> **Lưu ý cho lập trình viên đã dùng cổng thanh toán khác:** Webhook của ApiPay tương đương với khái niệm **IPN** (Instant Payment Notification) mà nhiều cổng thanh toán sử dụng. Luồng hoạt động giống nhau: đăng ký URL, nhận `POST` có chữ ký khi phát sinh giao dịch, và trả HTTP `200` để xác nhận.

## Đăng ký webhook

Bạn có thể tạo webhook URL trong dashboard tại **Cài đặt → Webhooks**, hoặc tạo bằng API.

Mặc định webhook là **toàn cục (global)**: nó gửi cho **tất cả tài khoản ngân hàng hiện tại và trong tương lai**. Bạn có thể thu hẹp phạm vi nếu cần:

- **Một ngân hàng (legacy)** — truyền `bankPublicId` để gắn webhook vào một ngân hàng đã kết nối. Vẫn được hỗ trợ cho các client cũ.
- **Danh sách ngân hàng đã chọn** — truyền `bankPublicIds: ["bnk_a", "bnk_b"]` để chỉ gửi cho các ngân hàng đó. Ngân hàng kết nối sau này **không** tự động được thêm vào.
- **Không ngân hàng nào** — truyền `bankPublicIds: []` để tạo webhook đã chọn nhưng hiện không khớp ngân hàng nào.

```bash
POST /v1/client/webhooks
```

### Request Body

| Tham số          | Kiểu     | Bắt buộc | Mô tả                                                                                                                     |
| ---------------- | -------- | -------- | ------------------------------------------------------------------------------------------------------------------------- |
| `webhookUrl`     | string   | **✓ Có** | HTTPS URL để nhận webhook                                                                                                 |
| `bankPublicId`   | string   | Không    | Legacy: gắn vào một tài khoản ngân hàng theo public ID                                                                    |
| `bankPublicIds`  | string[] | Không    | Danh sách ngân hàng được chọn. Bỏ trống (và không có `bankPublicId`) = tất cả ngân hàng; `[]` = không khớp ngân hàng nào |
| `isActive`       | boolean  | Không    | Tạo webhook ở trạng thái bật hoặc tắt (mặc định `true`)                                                                   |
| `timeoutSeconds` | integer  | Không    | Timeout mỗi lần gửi, 5–10 giây (mặc định `10`)                                                                            |
| `extraHeader`    | object   | Không    | Header tùy chọn `{name, value}`. `name` phải bắt đầu bằng `X-`                                                            |

> Không gửi đồng thời `bankPublicId` và `bankPublicIds`. API sẽ từ chối trừ khi chúng mô tả cùng một ngân hàng.

`timeoutSeconds` phải là số nguyên từ `5` đến `10`. Tham số này chỉ quy định thời gian ApiPay chờ endpoint của bạn ở mỗi lần gửi — lịch thử lại không đổi (xem [Retry policy](#retry-policy)).

### Response

```json
{
  "data": {
    "message": "Tạo webhook thành công",
    "id": "wh_abc123",
    "bankPublicId": null,
    "webhookUrl": "https://your-domain.com/webhooks/apipay",
    "secret": "a1b2c3d4..."
  }
}
```

`bankPublicId` là `null` với webhook toàn cục và webhook theo danh sách. Hãy lưu `secret`; khóa này dùng để kiểm tra `ApiPay-Signature`.

## Quản lý webhooks

| Endpoint                                             | Mô tả                                                     |
| ---------------------------------------------------- | --------------------------------------------------------- |
| `GET /v1/client/webhooks`                            | Danh sách webhook (`page`, `limit`)                       |
| `PATCH /v1/client/webhooks/:id`                      | Cập nhật URL, trạng thái, phạm vi ngân hàng, timeout, header |
| `PATCH /v1/client/webhooks/:id/toggle`               | Bật hoặc tắt webhook                                      |
| `DELETE /v1/client/webhooks/:id`                     | Xóa webhook                                               |
| `GET /v1/client/webhooks/:id/history`                | Xem lịch sử gửi (`page`, `limit`)                         |
| `POST /v1/client/webhooks/history/:historyId/resend` | Gửi lại một lần gửi thất bại                              |
| `GET /v1/client/webhooks/deliveries`                 | Xem lịch sử gửi webhook trên production, kèm bộ lọc       |

### Cập nhật webhook

```bash
PATCH /v1/client/webhooks/:id
```

| Tham số          | Kiểu             | Mô tả                                                                    |
| ---------------- | ---------------- | ------------------------------------------------------------------------ |
| `webhookUrl`     | string           | HTTPS URL mới                                                            |
| `isActive`       | boolean          | Bật hoặc tắt webhook                                                     |
| `bankPublicIds`  | string[] \| null | Danh sách ngân hàng. `null` = tất cả ngân hàng; `[]` = không ngân hàng nào; mảng = các ngân hàng đó |
| `timeoutSeconds` | integer \| null  | Timeout gửi 5–10. `null` đưa về mặc định `10`                            |
| `extraHeader`    | object \| null   | Header `{name, value}` tùy chọn. `null` để tắt                           |

Bỏ qua một trường để giữ nguyên, hoặc truyền `null` để đưa trường đó về mặc định:

```json
PATCH /v1/client/webhooks/wh_abc123
{
  "bankPublicIds": null,
  "timeoutSeconds": null,
  "extraHeader": null
}
```

Đặt `bankPublicIds` sẽ thay thế liên kết một ngân hàng (legacy). Muốn đưa webhook về lại một ngân hàng legacy, hãy xóa và tạo lại với `bankPublicId`.

### Response của danh sách

`GET /v1/client/webhooks` trả về mỗi webhook kèm phạm vi hiệu lực và cấu hình nâng cao:

| Trường          | Kiểu           | Mô tả                                                             |
| --------------- | -------------- | ----------------------------------------------------------------- |
| `bankAccountId` | number \| null | Liên kết một ngân hàng legacy; `null` với webhook toàn cục/đã chọn |
| `bankAccount`   | object \| null | Ngân hàng đã gắn khi `scope` là `bank`                            |
| `scope`         | string         | `all`, `selected`, hoặc `bank`                                    |
| `selectedBanks` | array          | Danh sách ngân hàng đã chọn khi `scope` là `selected`             |
| `configs`       | object         | `{bankPublicIds, timeoutSeconds, extraHeader}`                    |

`configs.bankPublicIds` là `null` khi webhook áp dụng cho tất cả ngân hàng. `configs.timeoutSeconds` luôn phản ánh giá trị hiệu lực (mặc định `10`).

## Lịch sử gửi (Delivery Log)

Lịch sử gửi webhook cho bạn xem lại mọi lần ApiPay gửi webhook trong môi trường production. Bạn có thể mở mục này từ **tab Lịch sử gửi** trên trang **Cài đặt → Webhooks** trong dashboard.

### Bộ lọc

| Bộ lọc      | Mô tả                                           |
| ----------- | ----------------------------------------------- |
| Khoảng ngày | Lọc theo ngày gửi                               |
| Ngân hàng   | Lọc theo tài khoản ngân hàng                    |
| Webhook     | Lọc theo endpoint cụ thể                        |
| Trạng thái  | `SUCCESS` (thành công) hoặc `FAILED` (thất bại) |

### Chi tiết bản ghi

Mỗi bản ghi trong Lịch sử gửi bao gồm:

- **Thời gian** — Thời điểm gửi webhook
- **Endpoint** — URL webhook đã gửi đến
- **Ngân hàng** — Tài khoản ngân hàng liên quan
- **Trạng thái** — Thành công hoặc thất bại, kèm mã phản hồi HTTP
- **Số lần thử lại** — Số lần hệ thống đã thử gửi lại
- **Mã tham chiếu** — Mã giao dịch liên quan
- **Số tiền** — Số tiền giao dịch

Nhấn vào một bản ghi để xem đầy đủ **nội dung phản hồi** (response body) từ server của bạn và **payload** mà ApiPay đã gửi.

### Gửi lại

Trong Lịch sử gửi, bạn có thể gửi lại ngay một webhook thất bại mà không cần rời khỏi trang.

### API

Truy vấn lịch sử gửi bằng API:

```bash

```

**Tham số truy vấn:**

## Xác thực webhook

Tất cả webhook requests đều có header `ApiPay-Signature` để bạn xác thực.

Chữ ký HMAC luôn được bật và không bị ảnh hưởng bởi bất kỳ cấu hình nào ở trên — `ApiPay-Signature` được gửi trong mọi lần gửi. `extraHeader` là header bổ sung, độc lập và không thay thế hay làm thay đổi chữ ký.

```javascript
const crypto = require("crypto");

function verifyWebhookSignature(payload, signature, secretKey) {
const expectedSignature = crypto
.createHmac("sha256", secretKey)
.update(payload)
.digest("hex");

    return crypto.timingSafeEqual(
    	Buffer.from(signature),
    	Buffer.from(expectedSignature),
    );

}

// Sử dụng trong Express
app.post("/webhook", (req, res) => {
const signature = req.headers["apipay-signature"];
const payload = JSON.stringify(req.body);

    if (!verifyWebhookSignature(payload, signature, process.env.WEBHOOK_SECRET)) {
````

```python
import hmac
import hashlib

def verify_webhook_signature(payload: str, signature: str, secret_key: str) -> bool:
    expected_signature = hmac.new(
        secret_key.encode(),
        payload.encode(),
        hashlib.sha256
    ).hexdigest()

    return hmac.compare_digest(signature, expected_signature)

# Sử dụng trong Flask
@app.route('/webhook', methods=['POST'])
def handle_webhook():
    signature = request.headers.get('ApiPay-Signature')
    payload = request.get_data(as_text=True)

    if not verify_webhook_signature(payload, signature, WEBHOOK_SECRET):
        return {'error': 'Invalid signature'}, 401

    data = request.get_json()
    event = data.get('event')

    if event == 'transaction.in':
        print(f"Tiền vào: {data['data']['amount']}")
        print(f"Mã tham chiếu: {data['data']['referenceCode']}")
        print(f"Nội dung: {data['data']['content']}")
        # Cập nhật đơn hàng
    return {'received': True}, 200
````

```php
<?php

use Illuminate\Http\Request;
use Illuminate\Support\Facades\Route;

function verifyWebhookSignature(string $payload, string $signature, string $secretKey): bool
{
    $expectedSignature = hash_hmac('sha256', $payload, $secretKey);

    return hash_equals($expectedSignature, $signature);
}

// Usage in Laravel route
Route::post('/webhook', function (Request $request) {
    $signature = $request->header('ApiPay-Signature');
    $payload = $request->getContent();

    if (!verifyWebhookSignature($payload, $signature, config('services.apipay.webhook_secret'))) {
        return response()->json(['error' => 'Invalid signature'], 401);

        logger('Reference: ' . $data['data']['referenceCode']);
        logger('Content: ' . $data['data']['content']);
        // Update order in your database
    }

    return response()->json(['received' => true]);
});
```

## Retry policy

- Lần 0: Ngay lập tức

Nếu webhook delivery thất bại, hệ thống sẽ thử gửi lại:

- Lần 1: Sau 5 giây
- Lần 2: Sau 20 giây
- Lần 3: Sau 1 phút

Sau 3 lần retry thất bại, webhook sẽ bị vô hiệu hóa.

`timeoutSeconds` quy định thời gian tối đa cho mỗi lần thử trước khi bị coi là thất bại. Tham số này không làm thay đổi lịch thử lại hay số lần thử.

## Test webhooks

Dùng [Webhook.site](https://webhook.site) để test webhook trong quá trình development:

1. Tạo URL test tại webhook.site
2. Cấu hình webhook URL trong dashboard
3. Tạo payment và hoàn thành thanh toán
4. Xem request trên webhook.site

## Best practices

1. **Luôn verify signature** trước khi xử lý webhook
2. **Response nhanh** - Trả 200 ngay, rồi xử lý async
3. **Idempotent** - Duplicate events không được làm cập nhật sai
4. **Log events** - Ghi log để debug khi cần
