# Sandbox

Sandbox giúp bạn tạo giao dịch ngân hàng thử và gửi webhook thật đến endpoint của mình. Không cần tiền thật, cũng không phải chờ một lệnh chuyển khoản thật. Dùng sandbox để kiểm tra luồng tích hợp trước khi bật production.

> **Có trên tất cả gói trả phí.** Bạn cần một gói đang hoạt động và ít nhất một tài khoản ngân hàng đã kết nối.

---

## Cách hoạt động

Sandbox dùng cùng cấu trúc payload webhook như production. Khi bạn trigger một sandbox run, ApiPay sẽ:

1. Tạo một giao dịch thử với mã tham chiếu riêng (`SBX-{timestamp}-{hex}`)
2. Tạo payload `transaction.in` giống webhook thật
3. Gửi **ngay** đến endpoint webhook của bạn, không đi qua hàng đợi
4. Lưu log gửi, gồm mã phản hồi và nội dung phản hồi

Payload có `"sandbox": true` để handler của bạn biết đây là sự kiện test.

---

## Bắt đầu

### Từ Dashboard

Vào **Sandbox** ở thanh bên trái. Trang này hiển thị:

- Tài khoản ngân hàng đang hoạt động
- Webhook đang hoạt động và ngân hàng được gắn với từng webhook
- Các sandbox run gần đây

### Cần chuẩn bị

Trước khi test, bạn cần có:

- Ít nhất một **tài khoản ngân hàng đang hoạt động** đã kết nối
- Ít nhất một **webhook đang hoạt động** cho tài khoản ngân hàng đó

Nếu chưa có webhook, vào **Cài đặt → Webhooks** để tạo trước.

## Chạy test

### Bước 1 — Tạo Payment Request

Điền form sandbox:

| Trường                | Bắt buộc | Mô tả                                                                    |
| --------------------- | -------- | ------------------------------------------------------------------------ |
| Tài khoản ngân hàng   | **Có**   | Chọn một ngân hàng đang hoạt động                                        |
| Số tiền               | **Có**   | Số nguyên VND, từ 1 đến 300.000.000                                      |
| Nội dung chuyển khoản | Không    | Nội dung hoặc ghi chú, tối đa 140 ký tự                                  |
| Tiêu đề               | Không    | Tên gợi nhớ cho lần test, tối đa 200 ký tự                               |
| Webhook đích          | Không    | Chọn một webhook cụ thể, hoặc để trống để gửi đến tất cả webhook phù hợp |

Nhấn **Tạo**. Lúc này hệ thống chỉ lưu payment request và tạo một run có trạng thái `CREATED`. Webhook vẫn chưa gửi.

### Bước 2 — Trigger giao dịch

Nhấn **Trigger** trên run. ApiPay sẽ:

- Tạo giao dịch thử
- Tìm webhook đích: webhook bạn đã chọn, hoặc tất cả webhook đang hoạt động khớp với chiều giao dịch của ngân hàng đó
- Gửi payload ngay
- Hiển thị kết quả trên trang

### Bước 3 — Xem kết quả

Mỗi run hiển thị:

- **Trạng thái run** — `SUCCESS`, `FAILED`, `PARTIAL`, hoặc `NO_WEBHOOKS`
- **Log gửi** — kết quả của từng webhook, gồm mã phản hồi HTTP và nội dung phản hồi (giới hạn 4 KB)
- **Payload** — JSON đã gửi

Nếu một lần gửi bị lỗi, bạn có thể bấm **Gửi lại** ngay trong trang chi tiết run.

## Payload Webhook

Payload sandbox giống production. Chỉ có hai điểm để nhận biết: `"sandbox": true` ở cấp cao nhất, và mã tham chiếu bắt đầu bằng `SBX-`.

### transaction.in (sandbox)

```json
{
  "event": "transaction.in",
  "sandbox": true,
  "data": {
    "transactionId": "clxyz...",
    "referenceCode": "SBX-1747123456789-A1B2C3D4",
    "amount": "50000",
    "type": "IN",
    "content": "ORDER-12345",
    "transactionDate": "2026-05-14T10:30:00.000Z",
    "bankAccountPublicId": "bk_abcdef1234567890",
    "gateway": "VCB",
    "rawTransactionDate": "2026-05-14 10:30:00",
    "vaNumber": "999988887777",
    "accountNumber": "0123456789"
  }
}
```

### transaction.out (sandbox legacy, đã deprecated)

Sandbox `transaction.out` đã deprecated từ tháng 6/2026 vì ApiPay không hỗ trợ sự kiện tiền ra. Test mới nên dùng `transaction.in`.

```json
{
  "event": "transaction.out",
  "sandbox": true,
  "data": {
    "transactionId": "clxyz...",
    "referenceCode": "SBX-1747123456789-E5F6G7H8",
    "amount": "200000",
    "type": "OUT",
    "content": "Hoàn tiền ORDER-12345",
    "transactionDate": "2026-05-14T10:31:00.000Z",
    "bankAccountPublicId": "bk_abcdef1234567890",
    "gateway": "VCB",
    "rawTransactionDate": "2026-05-14 10:31:00",
    "vaNumber": "999988887777",
    "accountNumber": "0987654321"
  }
}
```

### Nhận biết sự kiện sandbox

Trong handler, kiểm tra `sandbox: true` để bỏ qua phần xử lý đơn hàng khi đang test:

```javascript
app.post('/webhooks/apipay', (req, res) => {
  const {event, sandbox, data} = req.body;

  if (sandbox) {
    console.log('[sandbox] nhận sự kiện test:', event, data.referenceCode);
    return res.status(200).json({received: true});
  }

  // xử lý giao dịch thật
  if (event === 'transaction.in') {
    // xử lý đơn hàng...
  }

  res.status(200).json({received: true});
});
```

## Chọn webhook đích

Khi tạo sandbox payment request, bạn có thể chọn cách ApiPay tìm webhook:

**Chế độ broadcast** (mặc định, để trống trường webhook)
Tất cả webhook đang hoạt động trên tài khoản ngân hàng đã chọn sẽ nhận delivery. Cách này phù hợp khi bạn muốn kiểm tra routing.

**Chế độ đơn lẻ** (chọn một webhook cụ thể)
Chỉ webhook được chọn nhận delivery. Dùng cách này khi bạn muốn kiểm tra riêng một endpoint.

Bạn cũng có thể đổi webhook đích lúc trigger. Endpoint trigger nhận `webhookId` tùy chọn và sẽ ưu tiên giá trị này hơn webhook đã chọn lúc tạo.

---

## Trạng thái run

| Trạng thái    | Ý nghĩa                                                           |
| ------------- | ----------------------------------------------------------------- |
| `CREATED`     | Payment request đã lưu, chưa được trigger                         |
| `DELIVERING`  | Đang trigger                                                      |
| `SUCCESS`     | Tất cả webhook delivery thành công (HTTP 2xx)                     |
| `FAILED`      | Tất cả webhook delivery thất bại                                  |
| `PARTIAL`     | Một số thành công, một số thất bại                                |
| `NO_WEBHOOKS` | Không tìm thấy webhook đang hoạt động phù hợp. Không có gì để gửi |

---

## Gửi lại delivery

Nếu một delivery thất bại vì server của bạn đang down, trả về non-2xx, hoặc timeout, bạn có thể gửi lại từ trang chi tiết run. Không cần trigger lại toàn bộ run. Lần gửi lại dùng đúng payload ban đầu.

Mỗi delivery có số lần gửi lại riêng. Sau 3 lần, `nextRetryAt` sẽ được xóa. Bạn vẫn có thể gửi lại thủ công, nhưng lịch tự động sẽ dừng.

---

## Xóa lịch sử

Dùng nút **Xóa lịch sử** để xóa toàn bộ sandbox run của tài khoản. Đây là xóa cứng: run, giao dịch và log gửi đều bị xóa. Hữu ích khi bạn muốn dọn sạch dữ liệu giữa các buổi test.

---

## Mẹo

- Dùng [Webhook.site](https://webhook.site) hoặc [ngrok](https://ngrok.com) để test server local mà chưa cần deploy
- Nội dung chuyển khoản chỉ nên dùng chữ, số và các ký tự `. , - +`. Ký tự khác sẽ bị xóa trước khi lưu
- Mỗi payment request chỉ trigger được một lần. Tạo request mới cho mỗi lần test
