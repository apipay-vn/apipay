# MCP Server

`@apipay.vn/mcp` là máy chủ Model Context Protocol (MCP) của ApiPay. Trợ lý AI (Claude, Cursor, Codex, Gemini, Copilot…) dùng nó để tạo thanh toán, quản lý sản phẩm và mức giá, xem tài khoản ngân hàng và giao dịch, quản lý webhook và xem số liệu.

<Callout type="tip">
Mở **Tích hợp > Web App > MCP Server** trong dashboard để sao chép cấu hình đã điền sẵn khóa API.

[Mở MCP Server trong dashboard](https://my.apipay.vn/vi/integrations/mcp)
</Callout>

## Yêu cầu

- Node.js `>=18.0.0`
- Khóa API từ [dashboard ApiPay](https://my.apipay.vn): `ak_test_...` cho sandbox, khóa không có tiền tố cho production.

## Khóa API

Máy chủ đọc khóa API từ biến môi trường:

- `APIPAY_ACCESS_KEY` — access key (`ak_test_...` cho sandbox)
- `APIPAY_SECRET_KEY` — secret key
- `APIPAY_API_URL` — tùy chọn, mặc định `https://app.apipay.vn/v1`

Nếu không đặt biến môi trường, máy chủ dùng khóa API đã lưu bởi CLI ApiPay (`apipay login` rồi `apipay keys:create`).

## Cấu hình client

### File cấu hình JSON

```json
{
  "mcpServers": {
    "apipay": {
      "command": "npx",
      "args": ["-y", "@apipay.vn/mcp"],
      "env": {
        "APIPAY_ACCESS_KEY": "ak_test_your_access_key",
        "APIPAY_SECRET_KEY": "your_secret_key"
      }
    }
  }
}
```

Dùng cấu hình JSON ở trên cho các client sau:

| Client | Nơi thêm cấu hình |
| --- | --- |
| Claude Desktop | `claude_desktop_config.json` (macOS: `~/Library/Application Support/Claude/`) |
| Cursor | `.cursor/mcp.json` hoặc **Cursor Settings > MCP** |
| Windsurf | `.windsurf/mcp_config.json` |
| Cline | `cline_mcp_settings.json` |
| JetBrains AI Assistant | **Settings > Tools > AI Assistant > Model Context Protocol (MCP) > Add** |
| Warp | **Settings > AI > Manage MCP Servers > + Add** |

### CLI

```bash
# Claude Code
claude mcp add apipay --scope user \
  --env APIPAY_ACCESS_KEY=ak_test_your_access_key \
  --env APIPAY_SECRET_KEY=your_secret_key \
  -- npx -y @apipay.vn/mcp

# Codex
codex mcp add apipay \
  --env APIPAY_ACCESS_KEY=ak_test_your_access_key \
  --env APIPAY_SECRET_KEY=your_secret_key \
  -- npx -y @apipay.vn/mcp

# Copilot CLI
copilot mcp add apipay \
  --env APIPAY_ACCESS_KEY=ak_test_your_access_key \
  --env APIPAY_SECRET_KEY=your_secret_key \
  -- npx -y @apipay.vn/mcp

# Gemini CLI (thêm -s user để dùng cho mọi dự án)
gemini mcp add apipay \
  -e APIPAY_ACCESS_KEY=ak_test_your_access_key \
  -e APIPAY_SECRET_KEY=your_secret_key \
  -- npx -y @apipay.vn/mcp

# Grok Build
grok mcp add apipay \
  -e APIPAY_ACCESS_KEY=ak_test_your_access_key \
  -e APIPAY_SECRET_KEY=your_secret_key \
  -- npx -y @apipay.vn/mcp

# Command Code
cmd mcp add --transport stdio \
  --env APIPAY_ACCESS_KEY=ak_test_your_access_key \
  --env APIPAY_SECRET_KEY=your_secret_key \
  apipay -- npx -y @apipay.vn/mcp
```

Các CLI sau không truyền khóa API qua lệnh. Chạy `apipay login` rồi `apipay keys:create` trước:

```bash
amp mcp add apipay -- npx -y @apipay.vn/mcp       # Amp
devin mcp add apipay -- npx -y @apipay.vn/mcp     # Devin CLI
droid mcp add apipay "npx -y @apipay.vn/mcp"      # Factory CLI
qodercli mcp add apipay -- npx -y @apipay.vn/mcp  # Qoder CLI
```

## Công cụ có sẵn

### Kết nối

- `self_test` — Kiểm tra khóa API và kết nối, trả về tiền tố khóa và tổng quan tài khoản ngân hàng.

### Ngân hàng

- `list_banks` — Liệt kê tài khoản ngân hàng đã kết nối, kèm `bankPublicId` để tạo thanh toán và webhook.

### Yêu cầu thanh toán

- `create_payment` — Tạo link thanh toán. Cần `bankPublicId` và `amount` hoặc `priceId` (không gửi cả hai); tùy chọn `content`, `title`, `expiresAt`, `redirectUrl`. Có lookup key? Gọi `list_prices` để lấy `priceId`.
- `list_payments` — Liệt kê yêu cầu thanh toán, lọc theo trạng thái, từ khóa hoặc khoảng thời gian.
- `cancel_payment` — Hủy yêu cầu thanh toán đang `ACTIVE`.
- `simulate_payment` — Giả lập thanh toán sandbox (`publicId` bắt đầu bằng `test_pr_`) và gửi webhook thử.

### Sản phẩm & giá

- `list_products` — Liệt kê sản phẩm.
- `get_product` — Lấy một sản phẩm kèm các mức giá.
- `create_product` — Tạo sản phẩm; `defaultPriceData` tùy chọn tạo luôn mức giá mặc định.
- `update_product` — Sửa tên, mô tả, lưu trữ/khôi phục hoặc đổi giá mặc định.
- `list_prices` — Liệt kê mức giá, lọc theo `productId` hoặc `lookupKey`.
- `get_price` — Lấy một mức giá theo id.
- `create_price` — Tạo mức giá. Không sửa được số tiền sau khi tạo.
- `update_price` — Sửa tên nội bộ, lookup key hoặc lưu trữ/khôi phục.
- `delete_price` — Xóa mức giá chưa dùng. Mức giá đã có thanh toán chỉ lưu trữ được.

### Khách hàng & hóa đơn

- `list_commerce_customers` — Liệt kê khách hàng, tìm theo tên, email hoặc mã số thuế.
- `get_commerce_customer` — Lấy thông tin khách hàng kèm yêu cầu thanh toán và hóa đơn gần đây.
- `create_commerce_customer` — Tạo khách hàng. Email không được trùng.
- `update_commerce_customer` — Cập nhật thông tin khách hàng.
- `delete_commerce_customer` — Xóa khách hàng chưa có yêu cầu thanh toán hay hóa đơn.
- `send_commerce_invoice` — Gửi link thanh toán cho một mức giá đến email khách hàng.
- `list_commerce_invoices` — Liệt kê hóa đơn bán hàng, tìm theo số hóa đơn, người mua hoặc tên sản phẩm.
- `get_commerce_invoice` — Lấy chi tiết một hóa đơn.

### Webhook

- `list_webhooks` — Liệt kê webhook đã đăng ký.
- `create_webhook` — Đăng ký URL webhook cho một tài khoản ngân hàng.
- `update_webhook` — Đổi URL nhận webhook.
- `toggle_webhook` — Bật hoặc tắt webhook.
- `remove_webhook` — Xóa webhook.
- `list_webhook_deliveries` — Xem lịch sử gửi webhook.
- `resend_webhook` — Gửi lại một webhook thất bại.

### Số liệu & giao dịch

- `get_overview` — Tổng quan giao dịch: tổng, trung bình, tỷ lệ thành công, phân bổ theo ngân hàng.
- `list_transactions` — Liệt kê giao dịch gần đây, lọc theo ngày, ngân hàng hoặc từ khóa.

## Thử trong sandbox

1. Gọi `self_test` để kiểm tra khóa API.
2. Gọi `list_banks` để lấy `bankPublicId`.
3. Tùy chọn: gọi `create_product` với `defaultPriceData`, hoặc `list_prices` với `lookupKey` để lấy `priceId`.
4. Gọi `create_payment` với `bankPublicId` và `amount` (ví dụ `"100000"`) hoặc `priceId`. Khóa sandbox trả về `publicId` dạng `test_pr_...`.
5. Gọi `simulate_payment` với `publicId` đó để giả lập khách thanh toán.
6. Gọi `list_webhook_deliveries` và `list_transactions` để kiểm tra kết quả.

Xem thêm [Sandbox & Live Test](/vi/sandbox).

## Thao tác không hoàn tác được

<Callout type="danger">
Các công cụ sau xóa dữ liệu hoặc gửi request, email thật. Hãy để trợ lý AI xác nhận với bạn trước khi chạy:

- `cancel_payment` — Hủy link thanh toán đang hoạt động.
- `delete_price` — Xóa mức giá.
- `delete_commerce_customer` — Xóa khách hàng.
- `send_commerce_invoice` — Gửi email link thanh toán đến khách hàng.
- `remove_webhook` — Xóa webhook.
- `resend_webhook` — Gửi request thật đến URL webhook của bạn.
</Callout>
