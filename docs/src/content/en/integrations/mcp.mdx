# MCP Server

`@apipay.vn/mcp` is a Model Context Protocol (MCP) server for ApiPay. It exposes tools over stdio so AI assistants (Claude, Cursor, Codex, Command Code, Grok Build, Gemini, Copilot, OpenCode, and others) can create sandbox payments, list bank accounts and transactions, manage webhooks, and query metrics.

<Callout type="tip">
Open **Integrations > MCP Server** in the dashboard for copy-paste client configs with your API keys.

[Open MCP Server in dashboard](https://my.apipay.vn/en/integrations/mcp)
</Callout>

## Prerequisites

- Node.js `>=18.0.0`
- An ApiPay account with API keys from the [ApiPay Dashboard](https://my.apipay.vn) (`ak_test_...` for sandbox or `ak_live_...` for production)

## Authentication & Configuration

The MCP server authenticates requests with Base64-encoded `accessKey:secretKey` (`Authorization: Bearer <base64>`).

Configuration is loaded in this order:

1. **Environment variables**
   - `APIPAY_ACCESS_KEY` — merchant access key (`ak_test_...` or `ak_live_...`)
   - `APIPAY_SECRET_KEY` — merchant secret key
   - `APIPAY_API_URL` — optional base API URL (defaults to `https://app.apipay.vn/v1`)
2. **CLI configuration fallback** — if environment variables are missing, the server reads `~/.config/apipay/config.json` (the file managed by `apipay login` or `apipay keys:create`).

<Callout type="info">
The server starts even if credentials are not set. Individual tools return an error asking you to set credentials if they are called while unauthenticated.
</Callout>

## Client Setup

All examples use the same stdio server: `npx -y @apipay.vn/mcp`, with `APIPAY_ACCESS_KEY` and `APIPAY_SECRET_KEY` passed as environment variables. Use test keys (`ak_test_...`) in sandbox mode.

## Available Tools

The server registers 15 tools. MCP clients automatically prefix tool names with the server key `apipay` (for example `apipay_list_banks` in OpenCode, `mcp__apipay__list_banks` in Claude Code).

### Connection & Verification

- `self_test` — Validates API key configuration and returns connection status, key prefix, and bank summary counts.

### Banks

- `list_banks` — Lists connected bank accounts for this merchant (returns `bankPublicId` values needed to create payments and webhooks).

### Payment Requests

- `create_payment` — Creates a payment link (requires `bankPublicId`; optional `amount`, `content`, `title`, `expiresAt`, `redirectUrl`).
- `list_payments` — Lists payment requests with optional filtering by status, search term, or date range.
- `cancel_payment` — **(Destructive)** Cancels an `ACTIVE` payment request.
- `simulate_payment` — Simulates payment for sandbox requests (`publicId` must start with `test_pr_`; triggers sandbox webhooks).

### Webhooks

- `list_webhooks` — Lists registered webhook endpoints.
- `create_webhook` — Registers a webhook URL for a connected bank account.
- `update_webhook` — Updates the destination URL for a webhook.
- `toggle_webhook` — Toggles a webhook between active and inactive.
- `remove_webhook` — **(Destructive)** Permanently deletes a webhook.
- `list_webhook_deliveries` — Lists webhook delivery attempts and status logs.
- `resend_webhook` — Retries a failed webhook delivery (fires a real HTTP request to the destination).

### Metrics & Transactions

- `get_overview` — Returns transaction totals, averages, success rates, and bank volume distribution.
- `list_transactions` — Lists recent bank transactions with pagination, date, bank, and search filters.

## Typical Sandbox Workflow

1. **Verify connection** — Call `self_test` to confirm the API key is active.
2. **Find a connected bank** — Call `list_banks` to get a `bankPublicId`.
3. **Create a payment request** — Call `create_payment` with `bankPublicId` and `amount` (for example `"50000"`). A `publicId` starting with `test_pr_...` is returned.
4. **Simulate customer payment** — Call `simulate_payment` with `publicId: "test_pr_..."` to test settlement and webhook delivery.
5. **Check history** — Call `list_webhook_deliveries` and `list_transactions` to verify the transaction was recorded.

See [Sandbox & Live Test](/en/sandbox) for more on sandbox keys and simulated payments.

## Destructive Tools

<Callout type="danger">
These operations permanently change state or send a real outbound request. Agents should confirm before running them:

- `cancel_payment` — Cancels an active payment link.
- `remove_webhook` — Deletes a registered webhook URL.
- `resend_webhook` — Dispatches an HTTP request to the merchant webhook URL.
</Callout>
