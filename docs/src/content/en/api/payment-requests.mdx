# Payment Requests API

API for creating and managing payment links.

## Create Payment Link

Create a payment link using your connected bank account.

```bash
POST /v1/client/payment-requests
```

### Headers

| Header          | Description        |
| --------------- | ------------------ |
| `Authorization` | `Bearer <Auth>`    |
| `Content-Type`  | `application/json` |

> **Note:** `<Auth>` is your credentials encoded in base64. See [Authentication](/en/api/authentication) for details.

### Request Body

| Parameter      | Type   | Required  | Description                                                                                                                                                                                                                           |
| -------------- | ------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bankPublicId` | string | **✓ Yes** | Public ID of your connected bank                                                                                                                                                                                                      |
| `amount`       | string | —         | Amount in VND (integer string or number, max `300000000`). Returned as string or `null`. Leave empty to allow customer input. Do not send together with `priceId`                                                                     |
| `priceId`      | string | —         | Commerce price id. Copies that price amount onto this link once. Editing a product or price later does not change this request. Do not send together with `amount`. See [Commerce API](/en/api/commerce)                             |
| `content`      | string | —         | Transfer content (max 140 characters). If omitted on a `priceId` request, ApiPay stamps a unique memo from the payment-request public id                                                                                              |
| `title`        | string | —         | Title displayed on payment page                                                                                                                                                                                                       |
| `expiresAt`    | string | —         | Expiration time (ISO 8601). Leave empty for no limit                                                                                                                                                                                  |
| `redirectUrl`  | string | —         | URL to redirect after payment completion. When payment completes, the system will redirect to this URL with a signed payload (`?data=<base64>&signature=<hmac>`) for verification. Leave empty to use merchant's default redirect URL |
| `customer`     | object | —         | Optional buyer details on a one-time `priceId` payment (`name`, `email`, `taxCode`, `address`). Reusable payment-link checkout collects these on the pay page instead                                                                 |

### Response

```json
{
  "data": {
    "publicId": "APIPAYJSC69C3F00A3212",
    "payUrl": "https://pay.apipay.vn/APIPAYJSC69C3F00A3212",
    "qrUrl": "https://api.qrserver.com/v1/create-qr-code?...",
    "bankCode": "MB",
    "accountNumber": "0123456789",
    "accountName": "NGUYEN VAN A",
    "amount": "100000",
    "content": "ORDER-12345",
    "expiresAt": "2026-12-31T23:59:59Z",
    "createdAt": "2026-03-06T10:00:00Z",
    "redirectSecret": "a1b2c3d4e5f6..."
  },
  "statusCode": 200,
  "timestamp": "2026-08-12T14:27:45.000Z"
}
```

### Example

```bash
curl -X POST https://app.apipay.vn/v1/client/payment-requests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "bankPublicId": "bank_abc123",
    "amount": "500000",
    "content": "ORDER-001",
    "title": "Payment for Order #001",
    "redirectUrl": "https://yoursite.com/payment/result"
  }'
```

Create from a Commerce price (amount comes from the price; do not also send `amount`):

```bash
curl -X POST https://app.apipay.vn/v1/client/payment-requests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "bankPublicId": "bank_abc123",
    "priceId": "cml8x1abc0000price0000000",
    "content": "ORDER-001"
  }'
```

## List Payment Links

Get list of payment requests you've created. Endpoints payload lives under top-level `data`; list endpoints therefore have `data.data` for rows.

```bash
GET /v1/client/payment-requests
```

### Headers

| Header          | Description     |
| --------------- | --------------- |
| `Authorization` | `Bearer <Auth>` |

### Response

```json
{
  "data": {
    "status": true,
    "data": [
      {
        "publicId": "APIPAYJSC69C3F00A3212",
        "bankCode": "MB",
        "accountNumber": "0123456789",
        "accountName": "NGUYEN VAN A",
        "amount": "100000",
        "content": "ORDER-001",
        "title": "Payment for Order #001",
        "status": "COMPLETED",
        "expiresAt": "2026-12-31T23:59:59Z",
        "redirectUrl": "https://yoursite.com/payment/result",
        "commercePriceId": "cml8x1abc0000price0000000",
        "createdAt": "2026-03-06T10:00:00Z"
      }
    ],
    "pagination": {
      "page": 1,
      "limit": 20,
      "total": 1,
      "totalPages": 1
    }
  },
  "statusCode": 200,
  "timestamp": "2026-08-12T14:27:45.000Z"
}
```

### Query Parameters

| Parameter       | Type     | Required | Description                                            |
| --------------- | -------- | -------- | ------------------------------------------------------ |
| `page`          | number   | —        | Page number (default: `1`)                             |
| `limit`         | number   | —        | Items per page (default: `20`, max: `100`)             |
| `search`        | string   | —        | Search by public ID, content, title, or account number |
| `status`        | string[] | —        | Filter by status: `ACTIVE`, `EXPIRED`, `COMPLETED`, `CANCELLED`. Can be passed multiple times |
| `bankAccountId` | number   | —        | Filter by bank account ID                              |
| `dateFrom`      | string   | —        | Filter by creation date from this ISO date             |
| `dateTo`        | string   | —        | Filter by creation date through this ISO date          |

### Status Filters

The `status` query parameter accepts these values:

| Status      | Description         |
| ----------- | ------------------- |
| `ACTIVE`    | Waiting for payment |
| `COMPLETED` | Payment received    |
| `EXPIRED`   | Expired             |
| `CANCELLED` | Cancelled           |

### Query Examples

Get completed payment links:

```bash
curl -G https://app.apipay.vn/v1/client/payment-requests \
  -H "Authorization: Bearer <Auth>" \
  --data-urlencode "status=COMPLETED" \
  --data-urlencode "page=1" \
  --data-urlencode "limit=20"
```

Get active or expired payment links created in March 2026:

```bash
curl -G https://app.apipay.vn/v1/client/payment-requests \
  -H "Authorization: Bearer <Auth>" \
  --data-urlencode "status=ACTIVE" \
  --data-urlencode "status=EXPIRED" \
  --data-urlencode "dateFrom=2026-03-01" \
  --data-urlencode "dateTo=2026-03-31"
```

## Cancel Payment Link

Cancel an active payment request.

```bash
DELETE /v1/client/payment-requests/:publicId
```

### Response

```json
{
  "data": {
    "status": true,
    "message": "Payment request cancelled"
  },
  "statusCode": 200,
  "timestamp": "2026-08-12T14:27:45.000Z"
}
```

### Note

- Only payment requests with `ACTIVE` status can be cancelled
- After cancellation, status will change to `CANCELLED`

## Simulate Sandbox Payment

Mark a sandbox payment request as paid. Unauthenticated; `{publicId}` must start with `test_pr_`. No request body.

```bash
POST /v1/payment-requests/:publicId/pay
```

```bash
curl -X POST https://app.apipay.vn/v1/payment-requests/test_pr_abc123/pay
```

Live public IDs (for example `APIPAYJSC...`) return 400. See [Sandbox & Live Test](/en/sandbox).

## Signed Redirect URL Verification

When you provide a `redirectUrl` when creating a payment request, after payment completion, customers will be redirected to your URL with a signed payload.

### Redirect Format

After payment completes, customers are redirected to:

```
https://yoursite.com/payment/result?data=<base64>&signature=<hmac>
```

### Payload Structure

The `data` parameter contains a base64-encoded JSON object:

```json
{
  "status": "success",
  "transactionId": "txn_abc123",
  "amount": "100000",
  "content": "ORDER-12345",
  "timestamp": 1700000000
}
```

Possible `status` values: `success`, `cancel`, `expired`

### Verification Example

<CodeTabs>
```javascript
// Node.js example
const crypto = require('crypto');

function verifyRedirectPayload(query, redirectSecret) {
  // Decode the payload
  const payloadJson = Buffer.from(query.data, 'base64url').toString('utf-8');
  const payload = JSON.parse(payloadJson);

  // Calculate expected signature
  const expectedSignature = crypto.createHmac('sha256', redirectSecret).update(payloadJson).digest('hex');

  // Use timing-safe comparison to prevent timing attacks
  const isValid = crypto.timingSafeEqual(Buffer.from(query.signature), Buffer.from(expectedSignature));

  if (!isValid) {
    throw new Error('Invalid signature');
  }

  return payload;
}

// Express route handler
app.get('/payment/result', (req, res) => {
  const {data, signature} = req.query;
  const redirectSecret = 'a1b2c3d4e5f6...'; // From payment request response

  try {
    const payload = verifyRedirectPayload({data, signature}, redirectSecret);
    console.log('Payment status:', payload.status);
    console.log('Transaction ID:', payload.transactionId);
    console.log('Amount:', payload.amount);

    if (payload.status === 'success') {
      // Process the payment
      res.send('Payment successful!');
    }
  } catch (error) {
    res.status(400).send('Invalid redirect');
  }
});
```

```python
import hmac
import hashlib
import base64
import json

def verify_redirect_payload(query: dict, redirect_secret: str) -> dict:
    # Decode the base64url-encoded payload
    # Add padding if needed for standard base64 decoding
    data = query['data']
    padding = 4 - len(data) % 4
    if padding != 4:
        data += '=' * padding
    payload_json = base64.urlsafe_b64decode(data).decode('utf-8')
    payload = json.loads(payload_json)

    # Calculate expected signature
    expected_signature = hmac.new(
        redirect_secret.encode(),
        payload_json.encode(),
        hashlib.sha256
    ).hexdigest()

    # Use timing-safe comparison to prevent timing attacks
    if not hmac.compare_digest(query['signature'], expected_signature):
        raise ValueError('Invalid signature')

    return payload

# FastAPI route handler
@app.get('/payment/result')
def handle_redirect(data: str, signature: str):
    redirect_secret = 'a1b2c3d4e5f6...'  # From payment request response

    try:
        payload = verify_redirect_payload({'data': data, 'signature': signature}, redirect_secret)
        print(f"Payment status: {payload['status']}")
        print(f"Transaction ID: {payload['transactionId']}")
        print(f"Amount: {payload['amount']}")

        if payload['status'] == 'success':
            # Process the payment
            return {'message': 'Payment successful'}
    except ValueError:
        from fastapi import HTTPException
        raise HTTPException(status_code=400, detail='Invalid redirect')
```

```php
<?php

use Illuminate\Http\Request;

function verifyRedirectPayload(array $query, string $redirectSecret): array
{
    // Decode the base64url-encoded payload
    $data = strtr($query['data'], '-_', '+/');
    $payloadJson = base64_decode($data);
    $payload = json_decode($payloadJson, true);

    // Calculate expected signature
    $expectedSignature = hash_hmac('sha256', $payloadJson, $redirectSecret);

    // Use timing-safe comparison to prevent timing attacks
    if (!hash_equals($query['signature'], $expectedSignature)) {
        throw new \RuntimeException('Invalid signature');
    }

    return $payload;
}

// Laravel route handler
Route::get('/payment/result', function (Request $request) {
    $redirectSecret = 'a1b2c3d4e5f6...'; // From payment request response

    try {
        $payload = verifyRedirectPayload($request->query(), $redirectSecret);
        \Log::info('Payment status: ' . $payload['status']);
        \Log::info('Transaction ID: ' . $payload['transactionId']);
        \Log::info('Amount: ' . $payload['amount']);

        if ($payload['status'] === 'success') {
            // Process the payment
            return response('Payment successful!');
        }
    } catch (\RuntimeException $e) {
        abort(400, 'Invalid redirect');
    }
});
```

### Response Fields

When creating a payment request, you receive:

| Field                  | Description                                                                         |
| ---------------------- | ----------------------------------------------------------------------------------- |
| `redirectSecret`       | Secret key (32 hex chars) to verify signed redirect payloads. **Keep this secret!** |
| `completedRedirectUrl` | Full signed URL (available after payment completion) - for reference only           |

### Security Notes

- **Always verify the signature** before processing the payment
- Use `timingSafeEqual` to prevent timing attacks
- The `redirectSecret` is unique per payment request
- Never expose `redirectSecret` in client-side code
- Validate `status === 'success'` before fulfilling orders
