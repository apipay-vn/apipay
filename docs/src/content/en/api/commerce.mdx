# Commerce API

Create products and prices once, then create payment requests with `priceId` instead of `amount`. Every endpoint needs [authentication](/en/api/authentication). You can try the calls in the [Interactive Reference](/en/api-reference).

Every response is wrapped in `{"data": ..., "statusCode": 200, "timestamp": "..."}`. For Commerce, the result is in `data.data`; lists also have `data.pagination`.

## Endpoints

The paths below sit under `/v1/client/commerce`, except the two image endpoints, which show their full path.

| Method | Path | Description |
| ------ | ---- | ----------- |
| `POST` | `/products` | Create a product, optionally with a default price |
| `GET` | `/products` | List products (`active`, `page`, `limit`) |
| `GET` | `/products/:id` | Product with its prices |
| `PATCH` | `/products/:id` | Update a product |
| `POST` | `/prices` | Create a price |
| `GET` | `/prices` | List prices (`productId`, `lookupKey`, `active`, `page`, `limit`) |
| `GET` | `/prices/:id` | One price |
| `PATCH` | `/prices/:id` | Update a price |
| `DELETE` | `/prices/:id` | Delete a price that was never used |
| `GET` | `/invoices` | List receipts (`search`, `page`, `limit`) |
| `GET` | `/invoices/:id` | Receipt details |
| `GET` | `/invoices/:id/pdf` | Download the receipt PDF |
| `PATCH` | `/invoices/:id` | Update buyer details |
| `POST` | `/invoices/send` | Email a payment request |
| `GET` | `/customers` | List customers (`search`, `page`, `limit`) |
| `POST` | `/customers` | Create a customer |
| `GET` | `/customers/:id` | Customer details |
| `PATCH` | `/customers/:id` | Update a customer |
| `DELETE` | `/customers/:id` | Delete a customer |
| `POST` | `/v1/client/media` | Upload a product image |
| `DELETE` | `/v1/client/media/:id` | Delete an image |

## Create a product

```bash
POST /v1/client/commerce/products
```

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `name` | string | Yes | Product name (max 200 characters) |
| `description` | string | No | Basic HTML: `p`, `br`, `strong`, `em`, `u`, `s`, `a`, `ul`, `ol`, `li`, `blockquote`, `code`, `pre` (max 10,000 characters) |
| `defaultPriceData` | object | No | Creates the first price and makes it the default |
| `defaultPriceData.unitAmount` | string | Yes, if `defaultPriceData` is sent | Amount in VND, an integer from 1 to 300,000,000 |
| `defaultPriceData.lookupKey` | string | No | Your own lookup code, e.g. `pro-monthly` |
| `defaultPriceData.nickname` | string | No | Internal name, never shown to customers |

```bash
curl -X POST https://app.apipay.vn/v1/client/commerce/products \
  -H "Authorization: Bearer <Auth>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Pro plan",
    "description": "<p>Monthly access</p>",
    "defaultPriceData": {
      "unitAmount": "99000",
      "lookupKey": "pro-monthly",
      "nickname": "Launch price"
    }
  }'
```

```json
{
  "data": {
    "status": true,
    "data": {
      "id": "cml8x1abc0000prod0000000",
      "name": "Pro plan",
      "description": "<p>Monthly access</p>",
      "active": true,
      "imageId": null,
      "imageUrl": null,
      "defaultPriceId": "cml8x1abc0000price0000000",
      "defaultPrice": {
        "id": "cml8x1abc0000price0000000",
        "productId": "cml8x1abc0000prod0000000",
        "publicId": "plA2B3C4D5E6F7",
        "unitAmount": "99000",
        "currency": "VND",
        "lookupKey": "pro-monthly",
        "nickname": "Launch price",
        "active": true,
        "paymentLinkUrl": "https://pay.apipay.vn/p/plA2B3C4D5E6F7"
      },
      "activePriceCount": 1
    }
  },
  "statusCode": 201,
  "timestamp": "2026-09-04T10:00:00.000Z"
}
```

The example leaves out `prices`: every price of the product, in the same shape as `defaultPrice`.

## Update a product

```bash
PATCH /v1/client/commerce/products/:id
```

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `name` | string | No | Product name |
| `description` | string \| null | No | HTML description. Send `null` to clear |
| `active` | boolean | No | `false` archives, `true` restores |
| `defaultPriceId` | string \| null | No | An active price of this product. Send `null` to unset |
| `imageId` | string \| null | No | Image `id` from `POST /v1/client/media`. Send `null` to remove |

Editing a product never changes payment requests already created.

## Upload a product image

```bash
POST /v1/client/media
```

Send `multipart/form-data` with `file` (PNG, JPEG or WebP) and `kind=commerce_product`. Use the returned `id` as `imageId` when updating the product.

```bash
curl -X POST https://app.apipay.vn/v1/client/media \
  -H "Authorization: Bearer <Auth>" \
  -F "kind=commerce_product" \
  -F "file=@product.png"
```

## Create a price

```bash
POST /v1/client/commerce/prices
```

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `productId` | string | Yes | Product the price belongs to |
| `unitAmount` | string | Yes | Amount in VND, an integer from 1 to 300,000,000 |
| `lookupKey` | string | No | Lookup code, unique within your account |
| `nickname` | string | No | Internal name |
| `transferLookupKey` | boolean | No | `true` takes the `lookupKey` from the price that holds it instead of failing |

```bash
curl -X POST https://app.apipay.vn/v1/client/commerce/prices \
  -H "Authorization: Bearer <Auth>" \
  -H "Content-Type: application/json" \
  -d '{
    "productId": "cml8x1abc0000prod0000000",
    "unitAmount": "199000",
    "lookupKey": "pro-yearly",
    "nickname": "Yearly"
  }'
```

If the product has no default price yet, this price becomes the default. Find a price by its lookup code:

```bash
curl "https://app.apipay.vn/v1/client/commerce/prices?lookupKey=pro-monthly" \
  -H "Authorization: Bearer <Auth>"
```

## Update a price

```bash
PATCH /v1/client/commerce/prices/:id
```

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `active` | boolean | No | `false` archives, `true` restores |
| `nickname` | string \| null | No | Send `null` to clear |
| `lookupKey` | string \| null | No | Send `null` to clear |
| `transferLookupKey` | boolean | No | Take the `lookupKey` from the price that holds it |

`unitAmount` cannot be changed. To change a price, create a new one and archive the old one. Archived prices cannot be used for new payment requests; requests already created keep their amount.

## Delete a price

```bash
DELETE /v1/client/commerce/prices/:id
```

Only prices never used on a payment request can be deleted. A used price returns `409`; archive it with `PATCH` instead.

## Create a payment request from a price

Send `priceId` instead of `amount` (never both). The amount comes from the price; if you omit `title`, ApiPay uses the product name. `customer` is optional and pre-fills the buyer on the receipt.

```bash
curl -X POST https://app.apipay.vn/v1/client/payment-requests \
  -H "Authorization: Bearer <Auth>" \
  -H "Content-Type: application/json" \
  -d '{
    "bankPublicId": "bnk_abc123",
    "priceId": "cml8x1abc0000price0000000",
    "content": "DONHANG-001",
    "customer": {
      "name": "Nguyen Van A",
      "email": "customer@example.com"
    }
  }'
```

See [Payment Requests](/en/api/payment-requests) for the response and [Webhooks](/en/api/webhooks) for the payload sent when the customer pays.

Each price also has a `paymentLinkUrl`, a reusable payment link. Share it instead of creating a payment request per customer: the customer enters a name and email, then gets their own QR code.

## Receipts

When a customer pays through a link or payment request created from a price, ApiPay issues receipt `CINV-YYYYMM-XXXX` and emails the PDF to the buyer when an email is known (live transactions only).

<Callout type="warning">
A receipt records the payment between you and your customer. It is **not a VAT invoice**.
</Callout>

### List receipts

```bash
GET /v1/client/commerce/invoices
```

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `search` | string | No | Match receipt number, buyer name or email, product name |
| `page` | number | No | Page, default `1` |
| `limit` | number | No | Items per page, default `20`, max `100` |

### Details and PDF

`GET /invoices/:id` returns the seller, buyer, total and `lineItems`. `GET /invoices/:id/pdf` returns an `application/pdf` file.

### Update buyer details

```bash
PATCH /v1/client/commerce/invoices/:id
```

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `buyerName` | string | No | Buyer name |
| `buyerEmail` | string | No | Buyer email |
| `buyerTaxCode` | string | No | Tax code |
| `buyerAddress` | string | No | Address |

### Email a payment request

```bash
POST /v1/client/commerce/invoices/send
```

Creates a VietQR payment request and emails the link to the customer. Once they pay, the receipt is issued and emailed back. Sending too many in a short time returns `429`.

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `priceId` | string | Yes | An active price |
| `customerId` | string | One of the two | An existing customer |
| `customer` | object | One of the two | New customer: `name`, `email` required; `taxCode`, `address` optional |
| `expiresAt` | string | No | Payment deadline, ISO 8601 |

```bash
curl -X POST https://app.apipay.vn/v1/client/commerce/invoices/send \
  -H "Authorization: Bearer <Auth>" \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "cml8x1abc0000cust000000",
    "priceId": "cml8x1abc0000price0000000"
  }'
```

## Customers

### Create a customer

```bash
POST /v1/client/commerce/customers
```

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `name` | string | Yes | Customer name (max 200 characters) |
| `email` | string | Yes | Email, unique within your account (max 200 characters) |
| `taxCode` | string | No | Tax code (max 50 characters) |
| `address` | string | No | Address (max 500 characters), required when `taxCode` is set |

`PATCH /customers/:id` takes the same fields. Changing `email` to another customer's email returns `409`.

### List and details

`GET /customers` accepts `search` (name, email or tax code), `page` and `limit`. `GET /customers/:id` also returns the customer's latest payment requests and receipts.

### Delete a customer

```bash
DELETE /v1/client/commerce/customers/:id
```

A customer with payment requests or receipts returns `409`.
