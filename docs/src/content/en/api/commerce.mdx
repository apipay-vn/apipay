# Commerce API

Commerce API for products and prices. Authenticate like every other `/v1/client/*` endpoint. See [Authentication](/en/api/authentication).

After you have a price, create a payment link with `priceId` on [Payment Requests](/en/api/payment-requests). You can try these calls in the [Interactive Reference](/en/api-reference).

<Callout type="info">
Send `priceId` **or** `amount` when creating a payment — not both. The amount is copied onto the link once. Editing a product or price later does not change links already created.
</Callout>

## Endpoints

All paths are under `/v1/client/commerce`.

| Method | Path | Description |
| ------ | ---- | ----------- |
| `POST` | `/products` | Create a product. Optional `defaultPriceData` creates the first price and makes it the default |
| `GET` | `/products` | List products (`active`, `page`, `limit`) |
| `GET` | `/products/:id` | Get a product with its prices |
| `PATCH` | `/products/:id` | Update name, description, image (`imageId`), archive/restore, or default price |
| `POST` | `/prices` | Create a price. First price on a product with no default becomes the default |
| `GET` | `/prices` | List prices (`productId`, `lookupKey`, `active`, `page`, `limit`) |
| `GET` | `/prices/:id` | Get a price |
| `PATCH` | `/prices/:id` | Update `active`, `nickname`, `lookupKey`. Not `unitAmount` |
| `GET` | `/invoices` | List commerce invoices (`search`, `page`, `limit`) |
| `GET` | `/invoices/:id` | Get commerce invoice details with line items |
| `GET` | `/invoices/:id/pdf` | Download commerce invoice PDF receipt |
| `PATCH` | `/invoices/:id` | Update invoice buyer details (`buyerName`, `buyerEmail`, `buyerTaxCode`, `buyerAddress`) |

Public (no auth), used by `pay.apipay.vn`:

| Method | Path | Description |
| ------ | ---- | ----------- |
| `GET` | `/v1/commerce/payment-links/:publicId` | Product name, amount, and merchant branding for a reusable payment link |
| `POST` | `/v1/commerce/payment-links/:publicId/checkout` | Collect buyer details and mint a one-time payment request |
| `PATCH` | `/v1/payment-requests/:cuid/customer` | Collect buyer details on an existing commerce payment request before they pay |
| `POST` | `/v1/client/media` | Upload an image (multipart `file` + `kind=commerce_product`). Auth required |
| `DELETE` | `/v1/client/media/:id` | Delete an image you own. Auth required |
| `GET` | `/v1/media/:id` | Public image bytes (checkout and dashboard use this URL) |

Products return `imageId` / `imageUrl`. Attach an image with `POST /v1/client/media` then `PATCH /products/:id` with `imageId`. Send `imageId: null` to remove.

## Create a product

```bash
POST /v1/client/commerce/products
```

### Request body

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `name` | string | **Yes** | Product name (max 200) |
| `description` | string | — | Optional description (max 2000) |
| `defaultPriceData` | object | — | Create the first price and make it the default |
| `defaultPriceData.unitAmount` | string | **Yes** if `defaultPriceData` is sent | Amount in VND (integer string, 1–300000000) |
| `defaultPriceData.lookupKey` | string | — | Stable key you keep in your app, e.g. `pro-monthly` |
| `defaultPriceData.nickname` | string | — | Internal label only |

### Example

```bash
curl -X POST https://app.apipay.vn/v1/client/commerce/products \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "name": "Pro plan",
    "description": "Monthly access",
    "defaultPriceData": {
      "unitAmount": "99000",
      "lookupKey": "pro-monthly",
      "nickname": "Launch price"
    }
  }'
```

### Response

## Create a price

```bash
POST /v1/client/commerce/prices
```

Amounts cannot be edited later. To change what you charge, create a new price and archive the old one.

### Request body

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `productId` | string | **Yes** | Product this price belongs to |
| `unitAmount` | string | **Yes** | Amount in VND (integer string, 1–300000000) |
| `lookupKey` | string | — | Stable key unique per account. Use `GET /prices?lookupKey=` to find this price later |
| `nickname` | string | — | Internal label only |
| `transferLookupKey` | boolean | — | If `true`, move `lookupKey` off the price that currently holds it instead of failing |

### Example

```bash
curl -X POST https://app.apipay.vn/v1/client/commerce/prices \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "productId": "cml8x1abc0000prod0000000",
    "unitAmount": "199000",
    "lookupKey": "pro-yearly",
    "nickname": "Yearly"
  }'
```

If the product has no default price yet, this price becomes the default.

---

## Find a price by lookup key

```bash
curl "https://app.apipay.vn/v1/client/commerce/prices?lookupKey=pro-monthly" \
  -H "Authorization: Bearer <Auth>"
```

Use the returned `id` as `priceId` when creating a payment.

## Update a product

```bash
PATCH /v1/client/commerce/products/:id
```

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `name` | string | Product name |
| `description` | string \| null | Send `null` to clear |
| `active` | boolean | `false` archives, `true` restores |
| `defaultPriceId` | string \| null | Must be an active price of this product. Send `null` to clear |
| `imageId` | string \| null | Media id from `POST /v1/client/media`. Send `null` to remove |

---

## Update a price

```bash
PATCH /v1/client/commerce/prices/:id
```

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `active` | boolean | `false` archives, `true` restores |
| `nickname` | string \| null | Send `null` to clear |
| `lookupKey` | string \| null | Send `null` to clear |
| `transferLookupKey` | boolean | Move `lookupKey` from the price that currently holds it |

`unitAmount` is not accepted. Archived prices cannot be used to create new payment links. Links created earlier still point at the price they used (`commercePriceId` on the payment request).

## Create a payment from a price

```bash
curl -X POST https://app.apipay.vn/v1/client/payment-requests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "bankPublicId": "bank_abc123",
    "priceId": "cml8x1abc0000price0000000",
    "content": "ORDER-001"
  }'
```

The payment amount becomes the price `unitAmount`. If you omit `title`, the product name is used. You can also pass optional `customer` details to pre-populate the invoice buyer information:

```bash
curl -X POST https://app.apipay.vn/v1/client/payment-requests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "bankPublicId": "bank_abc123",
    "priceId": "cml8x1abc0000price0000000",
    "content": "ORDER-001",
    "customer": {
      "name": "Nguyen Van A",
      "email": "customer@example.com",
      "taxCode": "0101234567",
      "address": "123 Le Loi, Ben Nghe, Dist 1, HCMC"
    }
  }'
```

See [Payment Requests](/en/api/payment-requests) for the full response and [Webhooks](/en/api/webhooks) for what arrives after the customer pays.

Each price also has a reusable `paymentLinkUrl` (`https://pay.apipay.vn/p/{publicId}`). Share that URL instead of creating a payment request per customer. The pay page collects name and email, then mints a new payment request. After a live payment, the receipt PDF is emailed to the buyer.

## Commerce Invoices (Receipts)

When a live payment request with a `commercePriceId` completes, a paid `CommerceInvoice` is automatically created with an invoice number format of `CINV-YYYYMM-XXXX`.

<Callout type="warning">
**Notice**: Commerce invoices are commercial sales receipts issued by the merchant to confirm payment. They are **not official VAT invoices** (*"Đây không phải hóa đơn GTGT / This is not an official VAT invoice"*).
</Callout>

### List commerce invoices

```bash
GET /v1/client/commerce/invoices?search=CINV-202609&page=1&limit=20
```

| Query parameter | Type | Description |
| --------------- | ---- | ----------- |
| `search` | string | Filter by invoice number, buyer name, buyer email, or product name |
| `page` | number | Page number (default: 1) |
| `limit` | number | Items per page (default: 20, max: 100) |

### Get invoice details

```bash
GET /v1/client/commerce/invoices/:id
```

Returns the invoice details including seller details, buyer details, totals, and line items.

### Download invoice PDF

```bash
GET /v1/client/commerce/invoices/:id/pdf
```

Returns the binary `application/pdf` stream for the receipt, suggested filename `apipay-cinv-{invoiceNumber}.pdf`.

### Update invoice buyer details

```bash
PATCH /v1/client/commerce/invoices/:id
```

Update buyer information on an existing invoice if customer details were missing or need correction:

```bash
curl -X PATCH https://app.apipay.vn/v1/client/commerce/invoices/cml8x1abc0000inv0000000 \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <Auth>" \
  -d '{
    "buyerName": "Nguyen Van A",
    "buyerEmail": "buyer@example.com",
    "buyerTaxCode": "0101234567",
    "buyerAddress": "123 Le Loi, Dist 1, HCMC"
  }'
```
