# Bank Management

This page documents the actual client bank management API used to connect, verify, and manage bank accounts in ApiPay.

Base route:

```bash
/v1/client/banks
```

## API versions

ApiPay exposes two versions of the bank management API:

- **v1** (`/v1/client/banks`) — legacy flow keyed by `bankShortName`. Supports `ACB`, `BIDV`, `MBB`, `OCB`, `ICB`. Documented below.
- **v2** (`/v2/client/banks`) — current flow keyed by `bankBin` (bank BIN code). Supports all 8 banks below including the newer **VIB**, **Sacombank**, and **VPBank** integrations, plus the `business-household-account` account type. See [v2 reference](#v10-v2-bank-flow-bankbin).

## Valid bank codes

Use these `bankShortName` values for the v1 endpoints. New integrations (VIB, STB, VPB) and the `business-household-account` type are only available via v2 with `bankBin`.

| Code   | Bank        | BIN      | v1  | v2  | Account types                              |
| ------ | ----------- | -------- | :-: | :-: | ------------------------------------------ |
| `ACB`  | ACB         | `970416` | Yes | Yes | personal, business, household business     |
| `MBB`  | MB Bank     | `970422` | Yes | Yes | personal, business, household business     |
| `BIDV` | BIDV        | `970418` | Yes | Yes | personal, business, household business     |
| `OCB`  | OCB         | `970448` | Yes | Yes | personal, business, household business     |
| `ICB`  | VietinBank  | `970415` | Yes | Yes | personal, business, household business     |
| `VIB`  | VIB         | `970441` | No  | Yes | personal, business, household business     |
| `STB`  | Sacombank   | `970403` | No  | Yes | personal, household business (no business) |
| `VPB`  | VPBank      | `970432` | No  | Yes | personal, business, household business     |

## 1. Connect a bank account

```bash
POST /v1/client/banks
```

### Request body

```json
{
  "type": "openapi",
  "bankShortName": "MBB",
  "accountNumber": "24550721",
  "accName": "PHAM THANH DANH",
  "accMobile": "0858838502",
  "cccd": "012345678901"
}
```

### Business bank account

For business accounts, include `accountType: "BUSINESS"`.

ACB Onebiz business accounts also require the internet banking `username`:

```json
{
  "type": "openapi",
  "bankShortName": "ACB",
  "accountNumber": "24550721",
  "accName": "PHAM THANH DANH",
  "accMobile": "0858838502",
  "accountType": "BUSINESS",
  "username": "internet_banking_user"
}
```

MB Bank business accounts require the Tax code (MST) to be provided in `cccd`:

```json
{
  "type": "openapi",
  "bankShortName": "MBB",
  "accountNumber": "24550721",
  "accName": "PHAM THANH DANH",
  "accMobile": "0858838502",
  "cccd": "012345678901",
  "accountType": "BUSINESS"
}
```

### Important fields

- `type`: `openapi`
- `bankShortName`: one of `BIDV`, `ACB`, `MBB`, `OCB`, `ICB`, `VCB`
- `accountNumber`: bank account number
- `accName`: account holder name
- `accMobile`: phone number used for verification
- `cccd`: required for `BIDV`, `MBB`, and `ICB`
- `merchantId`: required for `BIDV`
- `accEmail`: required for `BIDV`
- `accountType`: set to `BUSINESS` for supported business bank accounts
- `username`: required for `VCB` or `ACB` when `accountType` is `BUSINESS`
- `password`: required for `VCB`

For `OCB`, only the base fields are required: `type`, `bankShortName`, `accountNumber`, `accName`, and `accMobile`.

### Response

ApiPay returns the connection result and includes the bank record when it is created or matched.

```json
{
  "status": true,
  "message": "Bank account submitted successfully",
  "bank": {
    "publicId": "bnk_abc123",
    "vaNumber": "DANH001",
    "status": "ACTIVE"
  }
}
```

Some banks require OTP verification, and in that case the system creates a local bank record with `PENDING` status first.

## 2. Confirm OTP for bank connection

```bash
POST /v1/client/banks/confirm-otp
```

### Request body

```json
{
  "bankShortName": "MBB",
  "accountNumber": "24550721",
  "accountName": "PHAM THANH DANH",
  "otp": "123456",
  "type": "openapi"
}
```

### Notes

- Use this endpoint when the connect step asks for OTP
- `merchantId` may still be required in some cases such as `BIDV`
- On success, matching local records move from `PENDING` to `ACTIVE`

## 3. List linked bank accounts

```bash
GET /v1/client/banks
```

### Response

```json
{
  "status": true,
  "message": [
    {
      "id": 12,
      "publicId": "bnk_abc123",
      "bankName": "MB Bank",
      "bankShortName": "MBB",
      "accountNumber": "24550721",
      "accountName": "PHAM THANH DANH",
      "vaNumber": "DANH001",
      "status": "ACTIVE",
      "createdAt": "2026-04-25T10:00:00.000Z"
    }
  ]
}
```

### Account statuses

- `ACTIVE`: enabled and usable
- `INACTIVE`: disabled
- `PENDING`: waiting for OTP or connection completion

## 4. Get a single bank account

```bash
GET /v1/client/banks/:publicId
```

### Success response

```json
{
  "status": true,
  "message": {
    "publicId": "bnk_abc123",
    "bankShortName": "MBB",
    "accountNumber": "24550721",
    "accountName": "PHAM THANH DANH"
  }
}
```

### Not found response

```json
{
  "status": false,
  "message": null
}
```

## 5. Get bank summary

```bash
GET /v1/client/banks/summary
```

### Response

```json
{
  "total": 3,
  "active": 2,
  "inactive": 1,
  "pending": 0
}
```

## 6. Toggle bank status

```bash
PATCH /v1/client/banks/:id/status
```

For this route, `:id` is the bank account `publicId`.

### Notes

- This only works for fully linked accounts
- If activation is not complete yet, the API returns an error

## 7. Disconnect a bank account

```bash
DELETE /v1/client/banks/:id
```

For this route, `:id` is the bank account `publicId`.

### Notes

- Some banks may require OTP confirmation before deletion
- If OTP is required, the API returns that verification step instead of deleting immediately

## 8. Confirm OTP for bank disconnection

```bash
POST /v1/client/banks/:id/confirm-delete
```

### Request body

```json
{
  "otp": "123456"
}
```

## 9. Remove an unconfirmed bank account

```bash
POST /v1/client/banks/remove-unconfirmed
```

### Request body

```json
{
  "bankShortName": "MBB",
  "accountNumber": "24550721"
}
```

Use this endpoint to clean up `PENDING` or otherwise unconfirmed bank records.

## 10. v2 bank flow (bankBin)

The v2 endpoints replace `bankShortName` with `bankBin` and add the household-business flow plus support for **VIB**, **Sacombank**, and **VPBank**. The Dashboard "Add Bank" page uses these endpoints.

### 10.1 Connect a bank account (v2)

```bash
POST /v2/client/banks
```

#### Request body

```json
{
  "bankBin": "970422",
  "bankName": "MB Bank",
  "accountType": "personal-account",
  "accountNumber": "24550721",
  "accountName": "PHAM THANH DANH",
  "mobile": "0858838502",
  "identity": "012345678901"
}
```

#### Fields

- `bankBin`: BIN of the target bank. Supported: `970416` (ACB), `970422` (MBB), `970418` (BIDV), `970448` (OCB), `970415` (ICB), `970441` (VIB), `970432` (VPB), `970403` (STB).
- `bankName`: full name of the bank (e.g., `MB Bank`).
- `accountType`: one of `personal-account`, `business-account`, `business-household-account`.
  - `STB` (Sacombank): only `personal-account` and `business-household-account` are accepted.
- `accountNumber`: bank account number.
- `accountName`: account holder name in CAPITAL LETTERS without accents.
- `mobile`: phone number registered with the bank for OTP.
- `identity`: CCCD (12 digits) for personal accounts on MBB, BIDV, ICB, VIB, STB, VPB; MST (Tax Code) for business / household business accounts. Not required for ACB.
- `acbUserId`: required for `ACB` when `accountType` is `business-account` (ACB OneBiz username).
- `merchantId`: required for `BIDV` personal accounts (Virtual Account merchant id).

#### Response — OTP required (online flow)

```json
{
  "OTP": 1,
  "bank": {
    "publicId": "bnk_abc123",
    "status": "PENDING"
  }
}
```

Call **`POST /v2/client/banks/confirm-otp`** with the OTP received on `mobile`.

#### Response — Manual activation queued

```json
{
  "activationRequested": true,
  "bank": {
    "publicId": "bnk_abc123",
    "status": "ACTIVATION_REQUESTED"
  }
}
```

Returned for connections that require ApiPay to sign an API contract before activation:

- `MBB`, `OCB`, `VIB`, `VPB` with `business-account` or `business-household-account`
- `BIDV`, `ICB` with `business-account`

The ApiPay team contacts you to complete the contract, then transitions the bank to `ACTIVE`.

### 10.2 Confirm OTP (v2)

```bash
POST /v2/client/banks/confirm-otp
```

```json
{
  "bankBin": "970422",
  "accountNumber": "24550721",
  "otpNumber": "123456"
}
```

### 10.3 List available banks (v2)

```bash
GET /v2/client/banks/available
```

Returns the catalog of banks the user can connect, including `bankBin`, `bankName`, `shortName`, and logo URL. Use the response to render the bank picker.

### 10.4 Other v2 endpoints

The v2 controller mirrors v1 for the remaining operations, using `:publicId` for path params:

- `GET /v2/client/banks` — list linked banks
- `GET /v2/client/banks/summary` — summary counts
- `GET /v2/client/banks/:publicId` — single bank
- `PATCH /v2/client/banks/:id/status` — toggle ACTIVE/INACTIVE
- `DELETE /v2/client/banks/:id` — disconnect (may require OTP)
- `POST /v2/client/banks/:id/confirm-delete` — confirm disconnect OTP
