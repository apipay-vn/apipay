# Sandbox

The sandbox lets you simulate bank transactions and fire real webhook deliveries to your endpoint — no real money, no waiting for an actual transfer. It's the fastest way to verify your integration is wired up correctly before going live.

> **Available on all paid plans.** You need an active subscription and at least one connected bank account to use the sandbox.

---

## How It Works

The sandbox mirrors the exact same webhook payload structure as production. When you trigger a sandbox run, ApiPay:

1. Creates a synthetic transaction with a unique reference code (`SBX-{timestamp}-{hex}`)
2. Builds the same `transaction.in` or `transaction.out` payload your live webhooks receive
3. Delivers it **synchronously** to your webhook endpoint — no queue, immediate result
4. Records the full delivery log including response code and body

The payload includes `"sandbox": true` so you can distinguish test events from real ones in your handler.

## Getting Started

### From the Dashboard

Go to **Sandbox** in the left sidebar. The page shows:

- Your active bank accounts
- Your active webhooks and which bank they're bound to
- Recent sandbox runs

### Prerequisites

Before running a sandbox test, make sure you have:

- At least one **active bank account** connected
- At least one **active webhook** configured for that bank account

If you don't have a webhook yet, head to **Settings → Webhooks** and create one first.

---

## Running a Test

### Step 1 — Create a Payment Request

Fill in the sandbox form:

| Field | Required | Description |
|-------|----------|-------------|
| Bank account | **Yes** | Pick one of your active connected banks |
| Amount | **Yes** | Integer VND, between 1 and 300,000,000 |
| Transfer content | No | The memo/description, max 140 characters |
| Title | No | A label for this test run, max 200 characters |
| Direction | No | `IN` (money received) or `OUT` (money sent) — defaults to `IN` |
| Target webhook | No | Send to a specific webhook, or leave blank to broadcast to all matching ones |

Click **Create** — this saves the payment request and creates a run in `CREATED` status. Nothing is delivered yet.

### Step 2 — Trigger the Transaction

Click **Trigger** on the run. ApiPay will:

- Generate the synthetic transaction
- Resolve the target webhooks (the one you selected, or all active webhooks matching the transaction direction on that bank)
- Deliver the payload immediately
- Show you the result inline

### Step 3 — Inspect the Result

Each run shows:

- **Run status** — `SUCCESS`, `FAILED`, `PARTIAL`, or `NO_WEBHOOKS`
- **Delivery log** — per-webhook result with HTTP response code and response body (truncated to 4 KB)
- **Payload** — the exact JSON that was sent

If a delivery failed, you can **Resend** it directly from the run detail view.

## Webhook Payload

Sandbox payloads are identical to production, with two additions: `"sandbox": true` at the top level, and a `SBX-` prefixed reference code.

### transaction.in (sandbox)

```json
{
  "event": "transaction.in",
  "sandbox": true,
  "data": {
    "transactionId": "clxyz...",
    "referenceCode": "SBX-1747123456789-A1B2C3D4",
    "amount": "50000",
    "type": "IN",
    "content": "ORDER-12345",
    "transactionDate": "2026-05-14T10:30:00.000Z",
    "bankAccountPublicId": "bk_abcdef1234567890",
    "gateway": "VCB",
    "rawTransactionDate": "2026-05-14 10:30:00",
    "vaNumber": "999988887777",
    "accountNumber": "0123456789"
  }
}
```

### transaction.out (sandbox)

```json
{
  "event": "transaction.out",
  "sandbox": true,
  "data": {
    "transactionId": "clxyz...",
    "referenceCode": "SBX-1747123456789-E5F6G7H8",
    "amount": "200000",
    "type": "OUT",
    "content": "Refund ORDER-12345",
    "transactionDate": "2026-05-14T10:31:00.000Z",
    "bankAccountPublicId": "bk_abcdef1234567890",
    "gateway": "VCB",
    "rawTransactionDate": "2026-05-14 10:31:00",
    "vaNumber": "999988887777",
    "accountNumber": "0987654321"
  }
}
```

### Detecting Sandbox Events

Check for `sandbox: true` in your handler to skip order fulfillment logic during tests:

```javascript
app.post('/webhooks/apipay', (req, res) => {
  const { event, sandbox, data } = req.body;

  if (sandbox) {
    console.log('[sandbox] received test event:', event, data.referenceCode);
    return res.status(200).json({ received: true });
  }

  // real transaction handling
  if (event === 'transaction.in') {
    // fulfill order...
  }

  res.status(200).json({ received: true });
});
```

## Webhook Targeting

When creating a sandbox payment request, you can choose how webhooks are selected:

**Broadcast mode** (default — leave webhook field empty)
All active webhooks on the selected bank account that match the transaction direction (`IN`, `OUT`, or `ALL`) will receive the delivery. Good for testing that your routing is correct.

**Single mode** (select a specific webhook)
Only the chosen webhook receives the delivery. Useful when you want to isolate a specific endpoint.

You can also override the target at trigger time — the trigger endpoint accepts an optional `webhookId` that takes precedence over the one set at creation.

## Run Statuses

| Status | Meaning |
|--------|---------|
| `CREATED` | Payment request saved, not yet triggered |
| `DELIVERING` | Trigger in progress |
| `SUCCESS` | All webhook deliveries succeeded (HTTP 2xx) |
| `FAILED` | All webhook deliveries failed |
| `PARTIAL` | Some deliveries succeeded, some failed |
| `NO_WEBHOOKS` | No active matching webhooks found — nothing was delivered |

---

## Resending a Delivery

If a delivery failed (your server was down, returned a non-2xx, or timed out), you can resend it from the run detail view without re-triggering the whole run. The resend uses the same payload that was originally sent.

Resend tracks a retry count per delivery. After 3 resends, `nextRetryAt` is cleared — you can still resend manually, but automatic scheduling stops.

---

## Clearing History

Use the **Clear History** button to wipe all sandbox runs for your account. This is a hard delete — runs, transactions, and delivery logs are all removed. Use it to keep your sandbox view clean between testing sessions.

---

## Tips

- Use [Webhook.site](https://webhook.site) or [ngrok](https://ngrok.com) to expose a local server for quick testing without deploying
- Test both `IN` and `OUT` directions if your integration handles both event types
- Keep the transfer content to plain letters, numbers, and the characters `. , - +` — anything else will be stripped before saving
- A payment request can only be triggered once; create a new one for each test run
