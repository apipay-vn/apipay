# Sandbox

Sandbox Mode gives you a safe, separate environment to test your integration end to end before going live. You get test API keys, a fake bank account, and test payment requests — everything behaves like production, but no real money moves and your live data is never touched.

No paid plan needed — just a verified, active account.

---

## Turn it on

Go to **Sandbox** in the left sidebar and switch on **Sandbox Mode**.

While it's on, the dashboard shows sandbox data only. Your live keys and live data are never affected.

---

## The test environment

Sandbox runs on its own resources, separate from production:

- **Test API keys** — created under API Keys, starting with `ak_test_`
- **A fake bank account** — created when you add a bank in sandbox
- **Test payment requests** — public IDs start with `test_pr_`
- **Sandbox webhooks and transactions** — separate from live ones

---

## Test flow

1. Turn on **Sandbox Mode**.
2. Create a test API key (starts with `ak_test_`).
3. Register a sandbox webhook and create a test payment request.
4. Simulate a transfer.
5. Check the webhook delivery log to confirm the round trip.
6. Clear history or reset sandbox anytime.

---

## Simulate a transfer

Two ways:

- **Transactions page** — use the sandbox transaction simulator to create a manual transaction.
- **Payment page** — open a test payment request (`test_pr_`) and pay it with the test button.

Either way, ApiPay sends the matching webhook to your sandbox webhooks.

---

## Check delivery

Open the webhook delivery log. A successful delivery confirms the sandbox round trip — same payload and signature flow as production.

### Sandbox payload

Webhook payloads are identical to production, with one addition: `"sandbox": true` at the top level, so your handler can tell test events from real ones.

```json
{
  "event": "transaction.in",
  "sandbox": true,
  "data": {
    "transactionId": "clxyz...",
    "referenceCode": "test_pr_...",
    "amount": "50000",
    "content": "ORDER-12345",
    "transactionDate": "2026-05-14T10:30:00.000Z",
    "bankAccountPublicId": "bk_abcdef1234567890",
    "gateway": "APIPAY",
    "rawTransactionDate": "2026-05-14 10:30:00",
    "vaNumber": "999988887777",
    "accountNumber": "0123456789"
  }
}
```

### Detecting Sandbox Events

Check for `sandbox: true` in your handler to skip order fulfillment logic during tests:

```javascript
app.post('/webhooks/apipay', (req, res) => {
  const {event, sandbox, data} = req.body;

  if (sandbox) {
    console.log('[sandbox] received test event:', event, data.referenceCode);
    return res.status(200).json({received: true});
  }

  // real transaction handling
  if (event === 'transaction.in') {
    // fulfill order...
  }

  res.status(200).json({received: true});
});
```

---

## Clear history vs reset

- **Clear history** — removes sandbox payment requests, transactions, and delivery logs. Your sandbox bank, webhooks, and API keys stay.
- **Reset sandbox** — removes everything sandbox-side: API keys, bank, webhooks, and history. Sandbox mode stays on; the test bank is recreated when you use it again.

---

## Tips

- Use [Webhook.site](https://webhook.site) or [ngrok](https://ngrok.com) to test against a local server without deploying
- Sandbox uses the same API as production — just swap in your test API key
- Test payment requests are marked with `test_pr_` so you can always tell them apart from live ones
